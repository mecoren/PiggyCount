# 端到端加密（E2EE）安全边界说明

> 对应审计项：SYNC-07（主密码无重输门控）、SYNC-08（派生密钥持久化）。
> 结论：当前实现为「可用性优先」的**有意设计取舍**，本文档显式声明其安全边界。

## 设计现状

开启端到端加密后：

1. **主密码 → 密钥派生**：主密码经 Argon2id（memory-hard）派生 256 位 AES 密钥，
   配合随机 salt 与 verifier 校验（`encryption_service_impl.dart`）。
2. **密钥持久化**：派生后的 AES 密钥与 salt 存入系统安全存储
   （Android EncryptedSharedPreferences / iOS Keychain，见 `secure_key_storage.dart`）。
3. **免重输**：App 启动后首次加解密操作会自动从安全存储加载密钥进内存
   （`_activeKey == null` 时 `_loadActiveKeyFromStorage()`），此后读写云端密文
   **无需再次输入主密码**。

## 安全边界（用户须知）

| 场景 | 防护情况 |
|---|---|
| 云端服务商 / 网络窃听 / 服务端被拖库 | ✅ 有效防护。服务端只见 E2EE 密文，无法解密账本内容 |
| 拿到云账号密码的攻击者 | ✅ 有效防护。云端另有密文 + 密码校验，无主密码不可读 |
| 设备丢失，未 root | ✅ 基本有效。系统级安全存储受锁屏凭据保护 |
| 设备被 root / 越狱后物理接触 | ⚠️ **有限防护**。攻击者若绕过系统安全存储，可直接取回已派生的 AES 密钥解密全部历史密文——**无需知晓主密码** |

第 4 行即本取舍的核心风险面：密钥落盘换取「日常使用零摩擦」。
替代方案是"密钥仅驻内存、每次冷启动重输密码"，代价是高频使用场景体验显著下降。

## 为什么不强制每次重输

- 记账为高频操作，同步在后台自动触发；每次唤醒都要求输入主密码会让
  自动同步形同虚设。
- 系统安全存储本身已有设备锁屏凭据作为第一道闸门；对绝大多数威胁模型，
  叠加重输密码属于重复加固。

## 用户侧缓解建议

- 在系统层启用强锁屏凭据 + 找回/远程擦除（Find My / 查找设备）。
- 主密码请勿与其他服务复用；设置入口已拦截常见弱密码并要求至少两类字符
  （SYNC-12 加固）。
- 怀疑设备被攻破时：立即在加密设置中执行「修改密码」（会重加密云端快照）
  并在其他设备重新激活密钥。
