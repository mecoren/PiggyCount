## 5. 问题分析与差异说明

### 5.1 唯一差异：`ledgers.is_shared / member_count` 不随快照同步（已知设计边界，非缺陷）

- **现象**：「家庭共用账本」A 端 `is_shared=1, member_count=2` → B 端 `0/1`。
- **根因（代码级证据）**：快照 JSON 账本元数据块仅含
  `version / exportedAt / ledgerId / ledgerName / currency / ledgerSyncId / monthStartDay / count`
  —— `lib/cloud/transactions_json.dart:437-458`（`version: 9`）。
  `is_shared / member_count / my_role` 属已下线的 PiggyCountCloud 实时协同协议元数据，路径 A 设计上不携带。
- **影响**：真实纯快照用户不会构造共享属性；该字段由测试注入脚本人为设置，无实际影响。
- **三轮印证**：2026-09-08 的 S3 轮、2026-09-08 的 WebDAV 轮、以及本轮（S3 + WebDAV）在**同一字段**上表现完全一致
  → 确认为设计边界而非实现缺陷。
- **建议**：若共享账本概念回归，需将其纳入快照 schema 并提升 `version`。

### 5.2 与 S3 轮的对照（差异分析）

| 对照项 | S3 轮 | WebDAV 轮 |
|---|---|---|
| 云端残留槽位 | 清理前有 5 个上轮残留同名槽位，本轮通过 syncId 对齐就地覆盖后消除 | 服务端以全新数据目录启动，**无任何历史槽位** |
| B 端云端发现数量 | 恰好 6（治理后） | 恰好 6 |
| B 端一键下载后一致性 | 完全一致 | 完全一致 |
| 上传时延 | 6 账本约 3 秒（云端 OSS） | 6 账本约 9.2 秒（本地 HTTPS 单文件服务器 + 每次 PUT/MOVE/OPTIONS/GET 串行） |
| 落盘持久化 | 对象存储（服务端不可直接检视） | 本地 `data/` 可直接检视 → 额外验证了原子写无残留、附件按 sha256 去重 |
| 交易逐字段差异 | 0 / 6006 | 0 / 6006 |
| 账本字段差异 | 1 项（is_shared/member_count） | 1 项（同上，表现完全相同） |

**结论**：后端差异未引入任何数据不一致；差异仅体现在传输时延与可观测性上。

### 5.3 落盘明文信封说明（非缺陷，配置相关）

- 服务端 LEDGER JSON 为 `{"fmt":"pc-wdav-env-v1","b64":false,"data":"<明文快照 JSON>"}` 信封。
- 原因：本轮两端均**未配置端到端加密（E2EE）**——prefs 中不存在任何 `encrypt*` 配置键。
  E2EE 为**可选功能**：用户开启后主密码经 Argon2id 派生 AES-256 密钥，云端落盘为密文。
- 依据：`docs/encryption-security-boundary.md`（端到端加密安全边界说明）。
- **测试范围声明**：本报告的「一致性」验证在未开启 E2EE 的配置下完成；E2EE 开启后的同步一致性属另一测试维度，本轮未覆盖。

### 5.4 测试环境治理与小问题（与被测功能无关，本轮已绕过）

| 问题 | 现象/根因 | 处置 |
|---|---|---|
| 无鉴权测试服务器硬编码绑定 `0.0.0.0` | 会把无鉴权服务暴露到局域网 | 启动器在内存中改写为 `127.0.0.1`（模拟器 `10.0.2.2` 映射宿主 loopback），fixture 不动 |
| `adb shell cat` 读二进制 | `\n→\r\n` 转换导致 sqlite 报 `database disk image is malformed` | 改用二进制安全的 **`adb exec-out`** |
| `adb push` | 既有报告称"大文件静默失败"；实测根因是 MSYS 路径 `/d/...` 被 adb 判为不存在 | 改用 **Windows 原生路径**，2.6MB 稳定成功 |
| `adb shell` 输出行尾 `\r` | 循环拼路径产生 `cp: bad 'xxx.jpg\r'` | 管道 `tr -d '\r'` |
| 运行中拉 sqlite | WAL 活跃导致副本损坏 | `force-stop` → 设备端 `sqlite3 "VACUUM INTO"` → `exec-out` |
| 应用启动未就绪即点击 | B 端首轮点击落空 | 每步点击后截图确认，再执行下一步 |
| 注入脚本缺 Pillow | 附件生成段 `ModuleNotFoundError` | 隔离 venv 安装 Pillow 12.3.0 |
| `seed_attachments/` 含 1 个孤儿文件 | 上一轮生成残留（内容未被任何 `transaction_attachments` 行引用），被推入设备但不上传 | 仅记录，不影响结果（服务端 6 个 `.bin` = 6 份唯一被引用内容） |

### 5.5 产品侧改进建议（用户可见）

1. **云端同名多槽位甄别**：「云端发现 / 全部恢复」对同名不同源账本应提示存在多槽位，或展示槽位 ID / 更新时间供用户甄别（S3 轮已暴露该场景）。
2. **云服务切换文案**：切换后端弹窗提示「将登出当前账号」可补充「已保存的凭据不会被删除」，降低用户对配置丢失的顾虑（本轮实测凭据确实保留）。
