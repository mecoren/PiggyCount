## 5. 问题分析

### 5.1 已知设计边界（非缺陷）：`ledgers.is_shared / member_count` 不随快照同步

- **现象**：「家庭共用账本」在 A 端 `is_shared=1, member_count=2, my_role=owner`，
  恢复到 B 端为 `is_shared=0, member_count=1`。**这是本轮唯一的字段差异。**
- **根因（代码级证据）**：快照 JSON 的账本元数据块仅含
  `version / exportedAt / ledgerId / ledgerName / currency / ledgerSyncId / monthStartDay / count`
  —— 见 `lib/cloud/transactions_json.dart:437-458`（`version: 9`）。
  `is_shared / member_count / my_role` 属已下线的 PiggyCountCloud 实时协同协议的共享元数据，
  路径 A（快照同步）设计上不携带。
- **影响**：真实用户若从不使用协同协议，不会构造出共享属性；本轮该字段由测试注入脚本人为设置。
  纯快照用户无实际影响。
- **建议**：若未来共享账本概念回归，需将这两个字段纳入快照 schema 并提升 `version`；当前保持现状即可。
- **跨轮次印证**：2026-09-08、2026-09-13（当日第一轮）与本轮共 4 次 S3/WebDAV 测试，
  在同一字段上呈现完全相同的表现，确认是设计边界而非实现缺陷。

### 5.2 环境/工具问题（与被测功能无关，本轮已绕过）

| 问题 | 现象 | 处置 |
|---|---|---|
| `adb shell cat` 读取二进制 | 输出被做 `\n → \r\n` 转换，拉取的 sqlite 报 `database disk image is malformed` | 改用 **`adb exec-out`**（二进制安全），字节数与设备端完全一致 |
| `adb push` 路径 | 传 MSYS 风格 `/d/...` 时 adb 报 `cannot stat`（历史报告中"大文件静默失败"的真实根因） | 改用 **Windows 原生路径** `D:/...`，2.6 MB 文件稳定推送成功 |
| `adb shell` 输出行尾 `\r` | 循环中用 `ls` 输出拼路径导致 `cp: bad 'xxx.jpg\r'` | 管道加 `tr -d '\r'` |
| 运行中拉取 sqlite | WAL 活跃，副本损坏 | `force-stop` → 设备端 `sqlite3 "... VACUUM INTO '...'"` → `exec-out` 拉取 |
| 非根目录写 `/data/local/tmp` 清理 | `run-as` 无权限删除 `/data/local/tmp` 下文件（Permission denied） | 无影响（tmp 残留仅占空间，不影响测试）；后续轮次不再依赖清理该目录 |
| 启动期瞬时告警 | `账本 1 不存在！ / 获取状态失败: 1`（`transactions_json.dart:433`） | 启动竞态：账本行尚未可见时计算状态，属既有噪声，不影响导入结果（后续导入 6/6 成功） |
