# WebDAV 同步功能测试报告（2026-10-24）

## 1. 结论

**通过（PASS）**。双端从空库起步，以 8 个账本 × 约 5000 笔交易（含 1999–2018 历史账本、微信 / 支付宝数据、持仓、储蓄目标、自定义字段、E2EE）完成 WebDAV 全量上传 / 全量下载 / 自动同步 / 立即备份 / 定时备份 / 从备份恢复；5 轮变更同步强校验与 G 轮最终收敛（含提醒补测）的契约内字段均为 **0 非预期差异**。

测试全程未删除、未重置、未改写云服务凭据或 E2EE 密钥：两端安全存储文件 sha256 与测试前一致（A `af1a6744…` / 2269B，B `17d8f173…` / 5805B），WebDAV 账号、S3 配置、加密密钥、自动同步开关均保留；仅通过 UI 切换当前云服务为 WebDAV。为实测定时备份，临时调整过本地 `backup_time` / 自动备份时间戳（§5.4，测试后恢复 22:00），不涉及云端凭据与密钥。

流程：A 端 UI 变更 → A 端「全量上传」（两层危险确认）→ B 端冷启动（发现云端账本跳过、云端更新暂不合并）→ B 端「全量下载」→ 两端 DB 快照逐契约字段比对。

| --- | --- | --- | --- | --- |
| R1 | 种子库首次上传，B 空库导入 | 完成（8 本） | 8/8 导入 | tx 40008 / 40008，✅ exit=0 |
| R2 | 金额 18.63→25.77；新增 66.66 后软删 | 40s | 60s | tx 40008 / 40008（A 回收站 1），✅ |

| R4 | 账户改名 HistCashR4；新增 555.55 后软删；软删 321.09 | 32s | 54s | tx 40008 / 40008（A 回收站 3、分类 28），✅ |

每轮比对结论均为：`无非预期差异`，仅存在契约外设备本地列（`created_at` 等，约 40150/40158 行）与回收站/行情缓存等设计内不同步项。

`mutation_check` 逐项核对：R2 金额改动、R3 账本改名 + 新增交易、R4 账户改名均在 B 端对应轮次同值落地；R4→R5 无交易/账本变更，符合预期。

| 差异项 | 观测 | 原因 |

| 附件 `created_at` | 每轮 9 行 | 各端本地写入时间，契约外字段，不参与同步 |

## 5. 专项功能验证

## 7. 问题与观察

1. **R4 测试脚本重复点击（测试工具问题，非产品缺陷）**：脚本在「删除后行文本仍匹配其他行」时重复点删除，自检误报失败，但两次软删均已落库（回收站 3 行）。重复点击期间还观察到未被引用的种子分类「测-转账」被删除，分类数 29→28；具体触发点在现有日志中无法还原。B 端全量下载后同为 28，两端一致。建议脚本给待删行加唯一 syncId 定位、删除后只校验该行。
2. **恢复与云端的语义**：从备份恢复只覆盖本地，云端仍是恢复前的数据；下次启动会按「云端更新」合并回来。若产品期望「恢复即云端回滚」，需补充流程或文案说明。
3. **启动合并弹窗阻塞定时备份**：`SyncRestoreGuard` 在等待用户确认「云端有更新」期间保持 busy，调度器日志显示「恢复进行中，本轮定时备份跳过」。保护逻辑正确，但日志措辞可区分「等待合并」与「恢复中」。
4. **同名备份覆盖**：定时/立即备份使用当日文件名 `PiggyCount-2026-10-24.zip`，同日多次备份会原子覆盖（`MOVE`）。测试可接受，生产需确认是否符合「保留当日最后一次」的产品预期。
5. 未发现账本缺失、交易重复/丢失、E2EE 解密失败或服务端 401/500 等异常。
