### 5.3 边界场景（跨后端共用代码路径）

**「远端删除是否镜像」**——本轮 S3 侧为验证 P0/P1 收敛，造数使用 `NO_DELETE=1`（不制造删除变更）。

- 默认「合并」路径 **不自动应用云端删除**（`SyncChange.selected = selected ?? (type != SyncChangeType.deleted)`，防误删设计），且合并后校验「存在未应用的云端删除，本轮跳过回传以防删除复活」，并在云同步页账本状态行显示「有 N 条云端删除待处理（默认不自动应用；以云端为准请用下方『全量下载』）」（P3 新增可见性）；
- 需要删除生效时走「**全量下载**」→ `成功 8 个，失败 0 个` → 双端收敛为 0 差异。

### 9.4 修正后的结论

**主结论不变**：8 个业务实体在**同步契约字段**上双端完全一致；4 轮 `exit=0`；P0（账户/分类改名）、P1（账本 name/currency/msd 增量合并）、P2（合并性能）、P3（删除可见性）的端到端有效性结论**不受本次复核影响**。

**但验收口径必须收紧为**：

> 「双端数据完全一致」应表述为「**在同步契约字段范围内完全一致**」，不应表述为「全库全列逐字节一致」。存在 3 类契约外差异：① 云快照不携带的身份/时间戳列（`created_by_user_id`、`last_edited_by_user_id`、`created_at`、`updated_at`）；② 本轮注入脚本自造的数据（`is_shared`/`member_count`/`owner_user_id`/`ledger_members`）；③ 按设计只存本机的 `sync_op_log`。

**测试工具缺陷（已修）**：`compare_sync_final.py` 的 docstring 声称比对 `created_by`，但生效实现为 `tx_rows_exact()`（不含该列），且存在未被调用的死代码 `tx_rows()`。**已在 §10 完成 v3 改造**：SPEC 单一事实来源 + SPEC/schema 自检 + 删除死代码 + 契约外字段显式化 + 补齐 `original_amount`/`custom_values`/override/附件覆盖，并对历史 12 组快照回归（判定与 v2 逐轮一致）。详细说明见 `WebDAV同步功能测试报告_20260926_修复后终验.md` §11.5。
