## 4. 测试结论

**通过。** S3 快照同步在 **8 账本 / 40008 笔交易**（历轮 6.7 倍规模）/ 61 账户 / 29 分类 /

两端数据**逐字段完全一致**：

- A → 云端 → B 全链路（UI 双重确认全量上传 → `Post-upload verify passed` 回读校验 ×8 →
  B 端逐账本发现导入 8/8）行为正确；单账本 1.66MB 快照上传 + 回读校验平均 957ms；
- 每账本 5001 笔 `成功=5001 失败=0`，无跳过、无丢单，500 条/批事务批量导入（单账本 ~0.4s）；
- 8 张同步表的 syncId 身份集合无任何单边缺失；
- 1999-2018 二十年历史数据 + 近期数据跨世纪混合同步无异常（逐年分布双端完全一致）；
- 微信/支付宝 16 组口径（笔数+净额）逐组相同，含历史账本移动支付时代分界（2011-08）数据；
- 附件内容身份与挂载关系完全一致，物理文件双端 md5 相同（含 1 例跨账本同内容去重）；
- 云端槽位与本地账本一一对应（B 端恰好发现 8 个，无残留干扰）；
- **云备份配置在清理 → 后端切换 → 注入 → 同步全流程零改动**（SecureStorage 逐字节不变，
  cloud_active_type 仅按 UI 操作从 webdav → s3 变更，WebDAV 凭据保留可切回）。

## 5. 问题分析

### 5.1 已知设计边界（非缺陷）：`ledgers.is_shared / member_count` 不随快照同步

- **现象**：「家庭共用账本」A 端 `is_shared=1, member_count=2`，B 端恢复为
  `is_shared=0, member_count=1`。**本轮唯一字段差异**，与 2026-09-08、09-10、09-13×2、
  09-14×2 共 6 轮测试表现完全一致。
- **根因**：快照 JSON 账本元数据块（v9，`lib/cloud/transactions_json.dart`）设计上仅含
  `version/exportedAt/ledgerId/ledgerName/currency/ledgerSyncId/monthStartDay/count`，
  共享属性属已下线协同协议，快照路径不携带。
- **影响**：真实用户不使用协同协议就不会有共享属性；本轮该字段由注入脚本人为设置。无实际影响。

### 5.2 环境/工具问题（与被测功能无关，已识别并规避）

1. **MSYS 路径转换破坏 adb 远端路径**：Git Bash 会把 `/data/local/tmp/...` 等远端路径
   重写为 `D:/DevTools/Git/data/local/tmp/...`，导致首轮 `adb push` 附件循环静默失败、
   DB 推回后误复核到旧库（发现于设备端行数复核 6 账本/6000 交易 ≠ 注入 8/40000）。
   规避：全程 `export MSYS_NO_PATHCONV=1` 后重推并复核通过（16.2MB DB + 7 附件）。
   该问题为本轮新识别，后续轮次直接前置规避。
2. **uiautomator dump 陈旧缓存**：与 09-14 轮相同，dump 前 `pkill -f uiautomator`。
3. **logcat 环形缓冲**：上传/导入期间日志量大，全程多段落盘
   （`s3_a_logcat_full.txt` / `s3_b_logcat_full2.txt`），`sync_op_log` 落库记录交叉印证。
4. **环境 grep 别名**：本机 `grep -t` 与 ugrep 冲突，改用文件落盘 + 本地过滤。
