## 6. 问题分析

**本轮未发现产品缺陷。** 三处过程记录：

1. **S3 桶在测试起点为空（环境状态，非缺陷）**：清库后 A 端冷启动时「云端账本发现完成: 0 个」（耗时 44ms，无异常），经排查 S3 `list` 实现会抛错而不静默吞异常，判定为桶内此前确无对象（上一轮 S3 数据未留存）。A 端全量上传后 B 端即正常发现 8 个并导入 8/8，功能链路无异常。
2. **删除类变更的既定语义（SYNC-05，预期行为）**：合并方「一键应用全部」只应用默认勾选的 `added/modified`，`deleted` 默认不勾选（防误删设计）；因此 R2/R3 中 16 条删除在合并方**故意保留**，且 `StartupSyncChecker` 的**防删除复活守卫**会跳过自动回传（日志：`存在未应用的云端删除，本轮跳过回传以防删除复活`）。收敛走「另一端全量上传 + 再合并」路径，两轮均正常收敛且终态双端完全一致——**非数据不一致，是用户未勾选删除时的设计结果**。
3. **UI 自动化前置环境问题（已排除）**：测试起点后端为 `webdav` 且本地 WebDAV 测试服务未启动，每次冷启动弹「同步状态检查失败」模态遮罩吞掉点击，导致后端切换脚本连续失败两次。启动测试服务器后恢复正常；后续全部 UI 操作均走文本定位（`flows.py`/`uidrv.py`），未再发生坐标漂移。
