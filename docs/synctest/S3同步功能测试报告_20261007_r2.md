## 6. 问题分析

### 6.1 【风险·中】「从备份恢复」后方向断言仍误判 `localNewer`（13:47 版报告标记的 §6.6 未修复）

**现象**（实测日志，S3 轮 `S3ZC_16384_upload_applogs.txt`）：

```
1791359169513 [CloudSync] 同步状态: 1 -> SyncDiff.localNewer
1791359558593 [CloudSync] 缓存命中: ledgerId=1, diff=SyncDiff.localNewer
```

此刻**本地 40011 / 云端 40012**（云端多一笔来自 ④ 自动同步的 `77.77`）。按内容事实应为 `cloudNewer`；判定为 `localNewer` 会引导用户「上传覆盖」，把只存在于云端的那一笔静默抹掉。

**取证与归因**（`S3Z_restored2.sqlite` / `WDZ_restored.sqlite`，两后端一致复现）：

1. 恢复确实落了地板行：`sync_op_log` 中 `scenario='snapshot_restore' AND outcome='success'` 共 **9 行**（8 条逐账本 `ledger_id=1..8` + 1 条整轮 `ledger_id=NULL`）。
2. **地板对 `ledgers.updated_at` 生效**：逐账本 `MAX(ts)` 与 `ledgers.updated_at` 对比，8 个账本全部 `updated_at ≤ 地板`（如 ledger1 地板 `1791359154` / `updated_at 1791359152`），即被正确过滤。
3. 但 **`local_changes` 残留 1 行未推送**：

   ```
   id=40  type=category  entity_id=29  ledger_id=0  action=upsert  created_at=1791164563  pushed_at=NULL
   ```

   该行时间戳 `1791164563` = 注入种子库的时刻，即**恢复时未被 `_purgeStaleLocalChanges` 清掉的历史残留**（两后端、两轮恢复完全一致地残留同一行）。
4. 设计上「条件 b（`local_changes` 未推送行）**不设地板**」（依据是恢复事务内已清过期变更，留下的必是本机真实写入）。该前提在本轮实测中不成立 → 条件 b 恒真 → 方向落到 `localNewer`。

**影响**：`startup_sync_checker.dart` 只对 `cloudNewer` 弹窗，因此该误判**不会**在启动检查里提示用户；用户若按同步页指引点「上传」，则云端较新副本被回退（本轮收敛轮实测把云端 40012 覆写为 40011，只存在于云端的那一笔丢失）。

**建议**：`_purgeStaleLocalChanges` 需要覆盖「恢复事务之外的陈旧未推送行」（例如按 `created_at ≤ 快照 exportedAt` / `≤ 地板` 一并清理），或在 `_localChangeEvidence` 的条件 b 上同样套用恢复地板。

> 说明：13:47 版报告把该项标注为「✅ 已在 `90a015b0` 修复」。本轮在**同一设备、同一构建**（`flutter run` 于 14:46–14:47 重新构建，含该提交）上仍稳定复现，故该修复**未闭环**。该提交的单元测试 `test/cloud/local_change_evidence_test.dart` 按其提交说明「未运行」（本机 Dart VM 231 故障），仅过编译级诊断。

### 6.2 【文案/口径·轻】备份日志「整包」是本地 zip 长度，云端对象另有 E2EE 开销

实测同一份备份：

| 来源 | 数值 |
|---|---|
| App 日志 `[Backup] 备份完成: …(跳过=0, 附件总量=128KB, 整包=2.1MB)` | 整包 = **2.1MB** |
| 「从备份恢复」列表条目 / 云端对象实际大小 | **3.7 MB**（WebDAV 服务端实测 `3,891,711 B`，头部魔数 `BEECRYPT1:` = E2EE 信封） |

`cloud_backup_service.dart:367` 的 `整包=${zipData.length}` 取的是**本地 zip 长度**；而落云对象是 E2EE 信封（更大约 1.8×）。两数都正确，但「整包」一词容易被读成「云端这个包有多大」。建议改为「zip=」或补一句「云端信封后约 …」。

### 6.3 契约外字段差异 5150+ 行为何属预期

差异集中在 `created_at` / `updated_at` / `created_by_user_id` / `last_edited_by_user_id` / `is_shared` / `member_count` / `owner_user_id` / `cloud_file_id` / `cloud_sha256` / `tag_sync_ids_override` —— 均为设备本地写入时刻 / 本机身份 / 云端定位信息 / 覆盖语义索引列，**不进同步契约**，比对器已单列，不计入不一致。

### 6.4 回收站（`deleted_transactions`）两端不同，属设计行为

ZC 轮 `A=2 / B=0`。回收站是刻意的**设备本地态**：归档行进本地 `deleted_transactions` 表，不进快照 / 不进备份（`lib/cloud/` 零引用）。A 端软删的记录不会出现在 B 端回收站。
