## 6. 问题分析

**#1 E2EE 与 WebDAV 的兼容性表现良好**
- 未修复键名前，WebDAV 服务器（自建，不丢下划线头）其实可容忍 `_encmeta`；本轮修复（`encMetaKey` → `pc-encmeta`）对 WebDAV 路径同样生效且向后兼容。服务端对象均为密文信封，明文快照 JSON 不落服务器盘。

**#2（操作规程）B 端后端残留状态**
- WebDAV 轮开始时 B 端仍停留在 S3 后端（上一轮切换残留），首次下载发现的是 S3 桶数据（syncId 不匹配）。处置：清 B 库 → 跳过 S3 发现弹窗 → UI 切换到 WebDAV → 重新下载 8/8 成功。多后端轮换测试时每轮必须核对两端「当前后端」。

**#3（已知设计边界，非缺陷）`is_shared` / `member_count` 差异**
- 「家庭共用账本」两端字段：A=`(is_shared=1, member_count=2)`，B=`(is_shared=0, member_count=1)`，与 S3 轮一致——共享成员信息属设备本地语义，快照同步不搬运该视角字段，其余字段一致。
- **口径更新（同日）**：`compare_sync_final.py` 已把这两个字段列入「预期差异」白名单（ledgers 拆「同步字段严格比对」+「设备本地字段单列展示」，不计入 issues；退出码 0 = 无非预期差异）。用本轮同一对快照复跑（`wd_compare_result_whitelist.txt`）：

```
  [OK] ledgers 同步字段(name, currency, type, month_start_day, my_role) 一致（8个账本）
  [OK*] ledgers 设备本地字段(is_shared, member_count) 差异 1 个 —— 预期差异，不计入不一致
       4dc2d9e6 A=(1, 2) vs B=(0, 1)
===== 结论: 无非预期差异（另有 1 个账本的设备本地字段差异 is_shared, member_count，属预期） =====
exit=0
```
