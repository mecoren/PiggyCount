## 6. 问题分析

**#1（已修复的真 Bug）S3×E2EE 上传 403：元数据信封键名含下划线被 OSS 丢弃**
- 现象：开启同步密码后首次上传 8/8 失败——账本 1–3 `PutObject timed out after ~100s`（网络抖动，重试即恢复），账本 4–8 返回 `HTTP 403 Not all the signed headers are found in the request`。
- 根因：E2EE 元数据信封键原为 `_encmeta`，S3 客户端将其转为请求头 `x-amz-meta-_encmeta`（下划线头名）。S3 签名器把全部 `x-amz-*` 头计入 SignedHeaders，而 OSS 网关默认丢弃下划线头名（nginx `underscores_in_headers off`），服务端收到请求后缺已签名头 → 403。
- 修复：`lib/data/encryption/encrypted_cloud_storage.dart` 键名改为 `pc-encmeta`（连字符），保留 `legacyEncMetaKey = '_encmeta'` 读取端兼容（旧密文对象仍可解封）；`_unwrapMetadata` 同时匹配两键。单测 `encrypted_cloud_storage_metadata_test.dart` 新增 legacy 兼容用例，**12/12 通过，`dart analyze` 零告警**。重建 APK（`install -r` 保留数据）后重测 **8/8 成功**。

**#2（已知设计边界，非缺陷）`is_shared` / `member_count` 差异**
- 「家庭共用账本」两端字段：A=`(is_shared=1, my_role=owner, member_count=2)`，B=`(is_shared=0, my_role=owner, member_count=1)`。
- 说明：共享成员信息属于设备本地语义（快照同步不搬运「我所在设备视角」的成员视图），其余 5 字段（name/currency/type/month_start_day/my_role）一致。不影响记账数据一致性。
- **口径更新（同日）**：`compare_sync_final.py` 已把这两个字段列入「预期差异」白名单——ledgers 拆成「同步字段（严格比对）」与「设备本地字段（单列展示，不计入 issues）」，退出码 0 = 无非预期差异、2 = 存在不一致。用本轮同一对快照复跑（`s3_compare_result_whitelist.txt`）：

```

  [OK*] ledgers 设备本地字段(is_shared, member_count) 差异 1 个 —— 预期差异，不计入不一致
       9925dab3 A=(1, 2) vs B=(0, 1)
```

- 其余维度（accounts / categories / tags / 40008 笔 transactions / transaction_tags / budgets / recurring / exchange_rate_overrides）全部 `[OK]`。

**#3（运维经验）B 端后端残留状态**
- 测试中发现 B 端在后端切换后可能残留上一后端的激活状态，导致「下载到错误后端的数据」。处置：清 B 库 → UI 切换到正确后端（S3）→ 重新下载。后续多后端轮换测试时应在每轮开始核对 B 端「当前后端」标识。
- **前端改进（同日）**：「发现云端账本」弹窗已新增首行「当前后端：类型 · host · 桶/远端路径」，连错后端可在点「下载」前看出。新增 `lib/cloud/backend_identity.dart`（脱敏口径，复用 `obfuscatedUrl()`，不含凭据）+ 单测 `test/cloud/backend_identity_test.dart`（口径 7 例、不泄露凭据 3 例），`duplicate_slots_message_test.dart` 补后端行 3 例，合计 21/21 通过；两个调用点（启动检查 `WidgetRefDeps`、云同步页「同步云端」）均已接入。
