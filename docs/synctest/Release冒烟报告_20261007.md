安装后的包信息：`versionName=0.1.0`、`versionCode=1`、`minSdk=24`、`targetSdk=36`、`primaryCpuAbi=x86_64`。

> 签名说明：本机无 `android/key.properties`，`build.gradle` 走**兜底路径**（自动生成 `ci-debug.keystore` 签名）→ 产物可安装但**不适合上架**。CI 侧对应步骤为 `Setup Android signing from secrets (optional)`。

## 3. 手段限制（证据口径，务必知悉）

1. **release 包不可 debug**：`run-as com.wait.piggycount` 报 `package not debuggable`；设备 `uid=2000(shell)` 未 root ⇒ **无法直读业务库**（dev 轮那套 `run-as + sqlite3` 手段在 release 上全部失效）。
2. **截图全黑是环境问题，不是渲染问题** —— 本条做了**同机 A/B 对照**：

   | 对象 | 截屏体积 | 结论 |
   |---|---|---|
   | release 包（prod） | 18,223 B（纯黑帧） | 取不到像素 |
   | **dev 包（debug）** | **18,223 B（纯黑帧）** | 同样取不到 ⇒ 与 release 无关 |
   | 上一轮同设备截图（`scripts/live_db/emu1_home.png`） | 358,558 B | 当时能取到内容 |
   | 首启**系统**权限弹窗那一帧 | 有内容（可见「允许/不允许」） | 系统窗口可截，Flutter 硬件 surface 取不到 |

   ⇒ 判定为**模拟器 `screencap` 对 Flutter（Impeller/GPU）surface 的已知黑帧现象**，dev/prod 一并复现，**不能作为 release 渲染异常的证据**。
3. 因此本轮视觉证据缺位，结论**全部建立在语义树断言 + 功能回读 + 日志**三重判据上（已如实记录，未用截图冒充）。

## 5. 结论与残留风险

**可以进入正式发版流程**（`v*` tag 触发 `release.yml`）。已知残留：

1. **本机冒烟用的是兜底 debug keystore 签名**的包；正式产物的签名由 CI secrets 决定，两者不同源。若要在发布前验证**真实签名包**的安装/升级，需提供 `android/key.properties` 后重跑一轮。
2. **iOS 侧仅验证了 CI 能构建出 unsigned 产物**；真机/TestFlight 安装链路未验（本机无 macOS 设备与签名证书）。
3. **真机（非模拟器）未覆盖**：本轮仍是模拟器；按 ABI 拆包后 arm64 真机的安装/运行未实测（APK 内含库已核对齐备）。
4. 视觉证据缺位（§3.2）—— 若需要截图存档，可在模拟器侧用 `--enable-impeller=false` 重取，或改用设备自带截图。
