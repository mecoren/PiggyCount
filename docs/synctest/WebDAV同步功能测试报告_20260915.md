## 5. 问题分析

### 5.1 已知设计边界（非缺陷）：`ledgers.is_shared / member_count` 不随快照同步

- **现象**：「家庭共用账本」A 端 `is_shared=1, member_count=2`，B 端恢复为
  `is_shared=0, member_count=1`。**本轮唯一字段差异**，与本日 S3 轮及 2026-09-08、
  09-10、09-13×2、09-14×2 共 7 轮测试表现完全一致。
- **根因**：快照 JSON 账本元数据块（v9，`lib/cloud/transactions_json.dart`）设计上
  不携带共享属性（已下线协同协议字段）。
- **影响**：注入脚本人为设置的属性，纯快照用户无实际影响。

### 5.2 差异原因说明（一致性核对的完备性）

除 §5.1 唯一已知差异外，本轮**未发现任何其他数据不一致**：

- `sync_op_log` / `local_changes.pushed_at` 等纯本地调度/埋点表**不属于同步域**，
  比对工具按设计排除（快照 JSON 不携带、恢复端不重建，属两端本地运行态）；
- `sqlite_sequence` 等本地自增计数不依赖（身份对齐全部走 syncId）；
- 历史账本中 2011-08 前的交易不产生微信/支付宝记录（移动支付时代合理性造数），
  属测试数据规格而非同步差异（B 端忠实还原 A 端形态）。

### 5.3 测试操作侧说明（与被测功能无关）

1. **MSYS 路径转换**：与 S3 轮 §5.2-1 相同（Git Bash 重写 adb 远端路径），
   本轮全程前置 `export MSYS_NO_PATHCONV=1`，未再发生；中间一次 `/tmp` 落盘
   复核文件 0 字节为同源问题（MSYS `/tmp` 映射），改存项目目录后复核通过。
2. **uiautomator 陈旧缓存 / logcat 环形缓冲**：处置方式与 S3 轮一致
   （dump 前 `pkill`；关键日志多段落盘）。
3. WebDAV 服务端以本机 Python 后台进程运行，全程零手工干预 `data/` 目录
   （对象只经应用 PUT 写入）。
