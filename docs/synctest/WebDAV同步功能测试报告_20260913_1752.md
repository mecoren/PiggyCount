### 1.1 服务端绑定说明（安全边界）

测试服务器默认只绑回环 `127.0.0.1`：该 fixture **不强制鉴权**（用于规避 `webdav_client` 的
401 + keep-alive 竞态），绑 `0.0.0.0` 会把无鉴权服务暴露到局域网。Android 模拟器的
`10.0.2.2` 本就映射宿主 loopback，`127.0.0.1` 已足够。启动方式：

```bash
python scripts/webdav_test/webdav_server.py --host 127.0.0.1 --port 8443
# 启动前清空夹具：rm -rf data share && mkdir -p data share   → 服务端 0 对象起步
```

**服务端以空桶（0 对象）起步**，因此本轮**无需**任何云端残留槽位治理 —— 与 S3 轮形成对照。

**通过。** WebDAV 快照同步在 6 账本 / 6006 笔交易 / 48 账户 / 29 分类 / 15 标签 / 1748 条标签链接 /

- 全链路（A 上传 → 服务端原子落盘 → `Post-upload verify passed` 回读校验 → B 逐账本导入

## 5. 问题分析

### 5.1 已知设计边界（非缺陷）：`ledgers.is_shared / member_count` 不随快照同步

- **现象**：「家庭共用账本」A 端 `is_shared=1, member_count=2, my_role=owner` → B 端
  `is_shared=0, member_count=1`。**这是本轮唯一的字段差异。**
- **根因（代码级证据）**：快照 JSON 账本元数据仅含
  `version / exportedAt / ledgerId / ledgerName / currency / ledgerSyncId / monthStartDay / count`
  —— `lib/cloud/transactions_json.dart:437-458`（`version: 9`）。
  `is_shared / member_count / my_role` 属于**已下线的 PiggyCountCloud 实时协同协议**的共享元数据，
  快照同步（路径 A）设计上不携带。
- **影响**：纯快照用户不会构造出共享属性（本轮由注入脚本人为设置），无实际影响。
- **建议**：若共享账本概念回归，需把字段纳入快照 schema 并提升 `version`；当前保持现状。
- **跨后端印证**：同一字段在本轮 S3 与 WebDAV 表现**逐字节相同**，且与 2026-09-08、
  2026-09-13 第一轮的历史结论一致 → 确认是**设计边界**，不是某一后端实现的缺陷。

### 5.2 环境问题（与被测功能无关，已定位并消除）

| 问题 | 现象 | 根因 | 处置 |
|---|---|---|---|
| WebDAV 服务不可达 | A 端 `Failed to initialize WebDAV: Connection refused`；UI 弹「6 个账本同步状态检查失败（网络或超时），请检查网络后重试」 | 首次以 `nohup ... &` 启动的测试服务器随 shell 会话结束被回收（`netstat` 已无 8443 监听） | 改以**常驻后台任务**方式重新启动，确认 `LISTENING 127.0.0.1:8443` 后重跑；上传/导入全部成功 |
| 连接失败引发的状态误读 | 失败窗口内同步页显示「未配置云端」 | 初始化失败后状态回落，属既有降级展示逻辑 | 服务器恢复后状态自动回到「已同步（本地1001条）」 |
| 启动期瞬时告警 | `账本 1 不存在！ / 获取状态失败: 1`（`transactions_json.dart:433`） | 启动竞态：state 计算早于账本行可见 | 既有噪声，不影响导入（6/6 成功）；建议后续在探针侧加就绪门控 |
| 服务端进程终结 | 任务状态 `failed`（Duration 6m12s） | 测试结束后由会话主动 `Stop-Process` 终止，**属预期收尾动作** | 无影响；已确认 8443 不再监听 |

### 5.3 安全边界相关（如实声明，非缺陷）

- **E2EE 未启用**：本轮 prefs 中无任何 `encrypt*` / `e2ee` 键，因此服务端落盘为**明文信封**
  `{"fmt":"pc-wdav-env-v1","b64":false,"data":"<快照JSON>"}`。**本报告的"两端完全一致"结论仅覆盖
  未加密快照路径**；E2EE 开启后的同步一致性本轮**未覆盖**（见 `docs/encryption-security-boundary.md`）。
- **测试服务器不强制鉴权**：客户端预置 BasicAuth（服务器日志确认全部请求携带凭据），但服务器侧
  不强制校验 —— 这是 fixture 为规避 `webdav_client` 的 401 + keep-alive 竞态而有意设计，
  因此**只绑回环**，不对外暴露。生产实现走 HTTPS + 强制鉴权（`docs/s3-webdav-sync-audit-2026-09-08.md`）。
