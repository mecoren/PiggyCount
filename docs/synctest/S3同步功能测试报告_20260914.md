## 5. 问题分析

### 5.1 已知设计边界（非缺陷）：`ledgers.is_shared / member_count` 不随快照同步

- **现象**：「家庭共用账本」A 端 `is_shared=1, member_count=2`，B 端恢复为 `is_shared=0, member_count=1`。
  **本轮唯一字段差异**，与 2026-09-08、09-10、09-13 两轮共 4 次测试表现完全一致。
- **根因**：快照 JSON 账本元数据块仅含 `version/exportedAt/ledgerId/ledgerName/currency/ledgerSyncId/monthStartDay/count`
  （`lib/cloud/transactions_json.dart` v9）。共享属性属已下线协同协议，快照路径设计上不携带。
- **影响**：真实用户不使用协同协议就不会有共享属性；本轮该字段由注入脚本人为设置。无实际影响。

### 5.2 环境/工具问题（与被测功能无关，已识别并规避）

1. **uiautomator dump 返回陈旧缓存**：连续 dump 会拿到上次结果，导致一度误判「点击未生效」。
   规避：每次 dump 前 `pkill -f uiautomator`。这也解释了测试中段一次误触（对第二次危险确认弹窗
   的遮罩区域点击）——该误触未产生任何数据影响（最终全量上传仍以显式双确认完成，日志链完整）。
2. **`run-as` 无法写 `/data/local/tmp`**（本模拟器 shell 目录权限 771）：改用 `adb push` +
   `run-as cat` 重定向落位。
3. **adb shell cat 拉取文件 CRLF 膨胀**：`run-as cat` 输出经 Git Bash 管道会 CRLF 化（3064→3071 B），
   已在比对前归一化；DB 二进制拉取改用 `exec-out` 通道不受影响。
4. **logcat 环形缓冲被 uiautomator 日志冲掉**：上传期间多次 `pkill uiautomator` 产生大量系统日志，
   挤掉了部分 flutter 日志。核心证据已实时落盘（`s3_a_full_upload.log`、`s3_b_04_import.log`、
   设备端 `sync_op_log` 12 条 snapshot_upload success 计录可交叉印证）。
