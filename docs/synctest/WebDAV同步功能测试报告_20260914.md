  满足「不删除任何云备份」的测试约束；
- 内容寻址附件在「云端已有同 sha 对象」时正确跳过重复上传，服务端对象字节保持不变；
- B 端 6/6 账本导入成功（每账本 1001 笔，0 跳过 0 失败），附件 6/6 补齐；
- **云备份配置全流程零损毁**：S3 轮 → WebDAV 轮两次清库、两次后端切换后，
  两端 `FlutterSecureStorage.xml` / `FlutterSecureKeyStorage.xml` 与测试开始前的基线
  **仍逐字节相同**（S3 + WebDAV 两套凭据完整保留，可随时切回任一后端）。

## 5. 问题分析

### 5.1 已知设计边界（非缺陷）：`ledgers.is_shared / member_count` 不随快照同步

- **现象**：「家庭共用账本」A 端 `is_shared=1, member_count=2`，B 端 `is_shared=0, member_count=1`。
  **本轮唯一字段差异**，与本日 S3 轮及 2026-09-08/09-10/09-13 各轮完全一致。
- **根因**：快照 JSON 账本元数据块（v9）设计上不携带共享属性（已下线协同协议字段），
  代码依据 `lib/cloud/transactions_json.dart`。
- **影响**：注入脚本人为设置的属性，纯快照用户无实际影响。

### 5.2 测试操作侧说明（与被测功能无关）

1. **`auto_sync` 开关翻转**：S3 轮一次 UI 误触（对云同步页「自动同步账本」开关区域的
   无效坐标点击）把 16384 端 `auto_sync` 从 true 翻为 false。这是用户级设置（记账后自动
   上传），不属于云备份配置；对两轮测试无影响（两轮均走显式全量上传）。修复方式：
   用户在同步页重新打开即可。
2. **附件上传日志行缺失的原因**：本轮服务端已存在同 sha 的附件对象，上传端走
   「云端已存在 → 跳过」路径；按代码逻辑仅 `uploaded>0 || failed>0` 才输出
   「附件对象上传完成」日志行（`transactions_sync_manager.dart:1427`），纯跳过场景静默。
   服务端对象字节级核验（§3.3）证明该行为正确。
3. 其余工具问题（uiautomator 陈旧缓存、run-as 权限、CRLF）与 S3 轮 §5.2 相同，处置方式一致。
