## 2. 测试基线的曲折（影响对其他现象的理解）

原计划「两端各自全量下载」建立收敛基线，**失败**：下载后 A 端 8 本全部非 inSync
（7 本 `localNewer` + 1 本 `different`），日志给出关键行：

```
指纹不一致 本地: ad901fe5 云端: f995ba72 数量 本地5003/云端5003
```

—— 数量相同、内容不同。原因：**「全量下载（覆盖）」只覆盖交易与账本段，不覆盖本地独有的 user-global 实体**
（本轮 A/B 在本机经历过**另一阶段**的注入，`custom_field_definitions` 两端各 3 条但 syncId 互不相同）。
因此基线改用**发布式收敛**：`A 全量上传 → B 全量下载`，两端都成为「并集」，才拿到 8/8 `inSync` 的干净起点。

> 附带结论：跨阶段（或跨设备各自新建）的 user-global 实体差异**不会**被「全量下载」抹平；
> 想把某一端的内容作为权威，必须走「全量上传」发布。
> 另外本轮踩到一个方向判定的细节：**只删实体/改金额（笔数不变）时方向判 `different`**，
> **新增一笔（笔数变化）时 core 的 count 兜底判 `cloudNewer`** —— 这决定了下一次冷启动
> 会不会弹「云端有更新」遮罩、以及账本页那个 `diff == different` 才出现的「对比合并」入口能不能进。

## 3. 发现并修复的两项缺陷（含守门测试与端上复验）

### F-1【已修】同名不同 syncId 的自定义字段定义，被「全量下载（覆盖）」**删空**且云端的定义不落地

**修复前现象（双端实测）**：B 端全量下载后 `custom_field_definitions` **3 → 0**（云端该账本带 3 条）；
该账本恒 `SyncDiff.different`（`本地 e8241a2f / 云端 bdbf6277`，笔数相同）；值仍在但定义没了 →
编辑表单无渲染位（字段从 UI 消失）。

**根因链**：`importCustomFields`（`lib/services/data_import_service.dart`）匹配顺序 `bySyncId[sid] ?? byName[name]`，
同名命中后只对齐 `name/fieldType/sortOrder`、**不采纳云端 syncId**；紧随的镜像删除按 **syncId** 判「云端已删」
⇒ 本地行被删、云端那份又因「同名已存在」不新建 ⇒ 0 条。而 syncId 进指纹白名单
（`sync_fingerprint.dart` 的 `customFieldCanon` 含 `syncId`）⇒ 该账本永久 `different`。

**修复**（三处）：
1. `importCustomFields`：同名命中且本地 syncId ≠ 云端 → **采纳云端 syncId**（身份先统一）；
2. 新增 `CustomFieldRepository.renameFieldValueKey(...)`（+ Local 实现 + LocalRepository 转发）：
   把本账本交易 `custom_values_json` 里的旧键改名为新键（**不记 change**，纯身份迁移；
   键冲突时保留已存在的目标键 = 云端权威），否则合并路径（交易行保留）的值会成孤儿；
3. 值键迁移在采纳 syncId 的同一步完成，日志 `自定义字段定义归并(同名不同 syncId): …`。

**守门测试**（`test/cloud/custom_field_sync_test.dart`，2 例）：
- 覆盖下载路径：定义保留、`syncId` 收敛到云端、值键跟着迁移（注释里写明修复前会 3 → 0）；
- 合并路径 `importCustomFields`：采纳云端 syncId 并迁移值键（保留本机值）。

**端上复验（重装包后）**：把 A 端 3 个定义的 syncId 改写成全新 UUID（模拟另一台设备各自建的同名字段）
→ A 全量上传 → B 全量下载：

```
[DataImport] 自定义字段定义归并(同名不同 syncId): id=6 「发生日期」e5112f5c-… → 11d243b7-…，迁移值键 0 笔
[DataImport] 自定义字段定义归并(同名不同 syncId): id=4 「报销金额」267b2ade-… → d62665d3-…，迁移值键 0 笔
[DataImport] 自定义字段定义归并(同名不同 syncId): id=5 「发票号码」c9cc96bc-… → e7934ced-…，迁移值键 0 笔
```
两端 syncId 集合 **完全相同**（`A−B = ∅`、`B−A = ∅`），B 定义数 **3（修复前为 0）**，ledger 3 转 **`inSync`**。

### F-2【已修】恢复（覆盖下载）路径的镜像删除**漏了 v11 持仓 / v12 储蓄目标** → 账本永久 `localNewer`

**修复前现象**：B 端账本 1 在多次「全量下载」后**仍为 `localNewer`** —— 本地独有的储蓄目标
（A 端已删、云端没有）没有被覆盖下载清掉（`savings_goals=12`，A 端 11）。

**根因**：`_mirrorDeleteAbsentEntities`（`data_import_service.dart`）的分支只覆盖
预算 / 周期规则 / 自定义字段定义 / 分类 / 标签 / 账户，**没有** holdings / savings_goals；
而合并路径早已用 `SyncEntityKind.holding / savingsGoal` 认得它们（v11/v12 同批补齐）—— 两侧口径不对称。

**修复**：补两个分支，且**带段版本门控**（`holdings ≥ v11`、`savingsGoals ≥ v12` —— 与
`sync_fingerprint` / `transactions_json` 的 `sectionAbsent` 同口径；不过门控时旧快照整段缺失会被
`cloudXxxSyncIds.isEmpty` 命中「删光本账本所有带 syncId 的行」分支）；日志行同步补 `储蓄目标=/持仓=`。

**守门测试**（`test/backup/restore_ledger_from_json_test.dart`，4 例）：v12 删目标 / v11 不删目标（段门控）、
v11 删持仓 / v10 不删持仓（段门控）。

**端上复验（重装包后）**：B 全量下载 → B 账本 1 **转 `inSync`**，`savings_goals` **12 → 11**、
ledger1 目标只剩 `['新手机基金']`，日志：

```
[DataImport] H3 镜像删除(ledgerId=1): 预算=0 周期=0 自定义字段=0 储蓄目标=1 持仓=0 分类=0 标签=0 账户=0
```

> 两项修复的验证证据：`MGf1_A_check2.sqlite` / `MGf1_B_after.sqlite`（syncId 集合比对）、
> `MGf2_B.sqlite`（目标 12 → 11）、`MG0_16416_download_logcat.txt`（归并与镜像删除日志行）、
> `_p_f2verify.log` / `_p_f1_bdl.log`（两端 `inSync`）。

## 4. 逐场景记录（三个入口全部覆盖）

### 4.1 场景 A：不勾选删除 + 应用（云同步页「下载同步」）✅

**前置**（A 端 UI）：删 ledger 1 的储蓄目标「应急基金」（单次危险确认，3s 倒计时）+ 改一笔金额 → 全量上传。

**B 端预览**（`MGB_preview.xml`）：

```
同步预览
  修改 1 条 | 删除 1 条
  全选            [CheckBox] checked=False
  修改  10-10 测-餐饮-晚餐 -¥33.33 | 金额: 99999.0 → 33.33, …   [CheckBox] checked=True
  删除  储蓄目标「应急基金」 | 云端已删除，勾选后一并删除本地     [CheckBox] checked=False  ← SYNC-05
```

**结果弹窗**（`MGB_result_skip.xml`）：

```
有 1 个账本存在你未勾选的云端删除，已跳过回传（这些删除本轮不会生效，下次同步会再次提示）
```

**核对**：本地目标保留（`MGb1_B.sqlite`：`savings_goals=12`）✅；云端未被写回（此后仍 `localNewer`）✅；

**导航**：首页左上角账本胶囊 → 「选择账本」抽屉 →「管理账本」→ 账本管理页 → 点 `(ID:2)` 卡片 →

### 4.4 三条入口的方向判据差异（观测结论）

| 入口 | 触发判据 | 实测 |
|---|---|---|
| 启动遮罩 | 启动检查判为「云端有更新」（`cloudNewer` 等） | ✅ 4.2；只删实体/改金额（笔数不变）时**不弹**，需有笔数差异才稳定触发 |
| 云同步页「下载同步」 | 逐账本 diff 预览 | ✅ 4.1；**方向一旦变 `localNewer`（例如先做过一次「不勾选删除」的合并），该账本不再出候选**，App 自述「无候选账本，全部都是最新」 |
| 账本页「对比合并」 | `syncStatus.diff == SyncDiff.different`（`ledgers_page_new.dart:334-344`）；账本卡片**不显示**同步状态 | ✅ 4.3；`cloudNewer` / `localNewer` 时点卡片只切账本 + Toast，不弹冲突框 |

> 观察（待产品确认，非本轮缺陷）：**「不勾选删除 → 跳过回传」之后，该账本的实体删除条目在
> 「下载同步」入口不再出现（方向变 `localNewer`）**；此时账本页「对比合并」也进不去（要求 `different`）。
> 用户的可见出路只剩「全量上传（覆盖）」= 复活对端已删的实体，或手工删除本地实体。
> 本轮取得该观测两次（`MGC2_preview_timeout.xml` + `MGC2_logcat2.txt` 的
> `StartupSyncChecker: 无候选账本，全部都是最新`），建议后续单独复测收敛结论。

## 5. 工具/环境修正（本轮踩坑，已修入库或已记档）

| 项 | 现象 | 处置 |
|---|---|---|
| `scripts/sync_regression/uidrv.py` | 设备侧 `uiautomator` 进程**偶发卡死**：dump 既不输出也不写文件，之后每次 dump 都失败；旧实现只原样重试一次 → 调用方空转（本轮实测编排空转 5 分钟以上） | **已修入库**：失败后 `pkill -f uiautomator` 自愈再重试（最多 3 次） |

| 危险确认按钮文案 | 「删除储蓄目标」弹窗确认键 label 是**「删除」**，而 `flows.confirm_danger_dialogs` 找「确定/确认」→ 命中**正文字节点**（「确定删除「应急基金」吗？」）→ 点了正文、弹窗不动却报「已点」 | 驱动改为「等倒计时消失后取最靠下的『删除』节点」，并在脚本注释记录 |
| `run-as` 回推 DB | `adb shell run-as PKG sh -c "cp a b"` 的嵌套引号被 adb 本地 shell 吃掉 → 远端 `sh -c cp` + 位置参数 → cp 报 missing operand 而**静默不动文件**（设备 DB mtime/syncId 全未变） | 改 `adb shell run-as PKG cp <src> <dst>`（直接传参）；回推后必须删 `-wal/-shm`（否则 App 启动会重放旧 WAL 覆盖改动） |
| 启动遮罩轮询 | 自己轮询「看到首页就停」会**漏掉遮罩**（首页先渲染、遮罩后弹；本轮判 `cloudNewer`、启动检查报「发现 1 个候选账本」，脚本却报未出现遮罩） | 改用 `flows.boot(merge='each')`：它找遮罩 → 点「逐个确认」→ **立即返回**（不会碰随后的逐账本汇总对话框） |
| 账本页入口 | 胶囊打开的是「选择账本」抽屉（不是账本管理页）；需再点「管理账本」；卡片按 `(ID:n)` 定位 | 已封装进 `b_merge_checked` |
| 基线收敛 | 两端各自全量下载不收敛（见 §2） | 改「发布式」：A 全量上传 → B 全量下载 |

## 7. 结论与后续建议

1. **合并路径核心语义达标**：实体删除默认不勾选、纯删除时按钮禁用、勾选后落地、回传放行、
   未勾选则跳过回传且**告知用户** —— 四道闸门与三个入口全部实测覆盖。
2. **F-1 / F-2 已修复并验证**（§3），补 6 个守门测试；`flutter analyze --fatal-infos` 0 issue、
   全量 `flutter test +2173 ~1` 全绿、真机重装复验通过。
3. **待产品确认（§4.4）**：`不勾选删除 → 跳过回传` 之后该条目在「下载同步」入口消失、
   「对比合并」也进不去（方向 `localNewer`），用户可能无路可走。建议：在 `localNewer` 下也提供
   「核对云端删除」的操作入口，或在状态卡上给出明确指引。
4. **可选补测**：① 多账本候选时的逐账本汇总「跳过剩余」分支；②
   弱网/中断下的合并半途失败；③ 实体删除与「引用守卫」交互（删账户时其交易仍在本机）。
