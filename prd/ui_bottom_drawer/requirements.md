# 底部抽屉化改造需求文档

## 一、需求理解

用户要求将"记账"和"添加账户"两个核心入口从全屏页面改为底部弹出抽屉，参考 wait-home 项目影视模块的 `movie_form_bottom_sheet.dart` 实现模式。目标是让用户在不离开当前页面的情况下快速完成记账和添加账户操作，降低上下文切换成本。

## 二、用户故事

### US-1：记账底部抽屉
- **作为**用户，
- **我希望**点击记账按钮后从底部弹出抽屉，
- **以便**我能在当前页面快速完成记账，不需要跳转到新页面。

### US-2：添加账户底部抽屉
- **作为**用户，
- **我希望**在资产管理页点击添加账户按钮后从底部弹出抽屉，
- **以便**我能快速添加账户，不需要跳转到新页面。

## 三、功能需求

### 3.1 记账底部抽屉（US-1）

#### 必须实现
- 点击首页/任意页面的记账按钮后，从底部弹出抽屉
- 抽屉顶部显示分段选择器（支出 / 收入 / 转账）+ 关闭按钮
- 抽屉内容根据选中类型显示：
  - 支出/收入：分类选择器（CategorySelector）
  - 转账：转账表单（TransferForm）
- 点击分类后，在抽屉内切换到金额输入界面（AmountEditorSheet 内容），不再弹出新的 bottom sheet
- 金额输入界面包含：金额、日期、备注、账户选择、标签、不计入统计/预算开关
- 支持向上拖动扩展至全屏
- 支持向下拖动收起关闭
- 保存成功后自动关闭抽屉
- 键盘弹出时抽屉内容自动上移避让

#### 不在本次范围
- 语音记账、图片记账（保持现有入口）
- 快捷记账（quickAdd）逻辑变更
- 转账表单内部逻辑变更

### 3.2 添加账户底部抽屉（US-2）

#### 必须实现
- 点击资产管理页的添加账户按钮后，从底部弹出抽屉
- 抽屉顶部显示标题（新建账户/编辑账户）+ 关闭按钮 + 保存按钮
- 抽屉内容包含：
  - 账户类型 Tab（日常账户 / 估值账户）
  - 账户名称、类型选择、币种选择
  - 初始余额 / 估值（根据类型变化）
  - 信用卡：额度、账单日、还款日、提醒设置
  - 银行名、卡号后四位、备注
- 支持向上拖动扩展至全屏
- 支持向下拖动收起关闭
- 保存成功后自动关闭抽屉
- 键盘弹出时抽屉内容自动上移避让
- 表单校验失败时显示错误提示

#### 不在本次范围
- 账户类型枚举变更
- 信用卡提醒逻辑变更
- 账户排序逻辑变更

## 四、非功能需求

### 4.1 性能
- 抽屉弹出动画 ≤ 300ms
- 键盘弹出/收起时抽屉内容重建范围最小化（用 RepaintBoundary 隔离）
- 抽屉内滚动列表使用共享 ScrollController 与 DraggableScrollableSheet 联动

### 4.2 兼容性
- 保留 `TransactionEditorPage` 和 `AccountEditPage` 原类（其他入口可能仍使用）
- 新增 `showTransactionFormBottomSheet()` 和 `showAccountFormBottomSheet()` 作为抽屉入口
- 首页记账按钮、资产管理页添加按钮改为调用新入口
- 不破坏现有的 AppLink 深链、QuickActions 快捷方式

### 4.3 视觉规范
- 抽屉顶部圆角使用 `PiggyDimens.radiusXl` (16dp)
- 抽屉背景色使用 `PiggyTokens.surface(context)`
- 拖动指示条（drag handle）样式与项目其他底部弹窗一致
- 标题栏使用 `GlassTitleBar`（blur: false, showHighlightLine: false）保持与 wait-home 实现一致

### 4.4 国际化
- 复用现有 l10n key，不新增 key（除非必要）
- 标题、按钮文字与原页面保持一致

## 六、风险与边界条件

1. **AmountEditorSheet 改造风险**：当前 AmountEditorSheet 是独立 showModalBottomSheet，改造为抽屉内切换需要调整其生命周期和回调
2. **TransferForm 嵌套风险**：TransferForm 内部可能有 Navigator 调用，放在抽屉内可能冲突
3. **键盘避让风险**：抽屉 + 键盘 + DraggableScrollableSheet 三者协调，需用 `_KeyboardBottomPadding` 隔离 viewInsets 重建
4. **AppLink 兼容风险**：AppLink 深链可能直接 push TransactionEditorPage，需保留原页面入口
5. **编辑模式风险**：编辑现有交易/账户时是否也用抽屉，还是保留全屏页（建议编辑模式仍用全屏页，新建模式用抽屉）
