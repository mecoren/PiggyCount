# PiggyCount 云端全量备份与全量覆盖需求文档

> 版本：v1.0  日期：2026-08-16
> 关联设计：`/prd/cloud_backup/design.md`

---

## 1. 背景与目标

### 1.1 背景

PiggyCount 现有云同步为「快照式同步」：每个账本一个 `ledger_<id>.json` 上传覆盖云端，云端始终只有**最新一份**状态，无历史版本。用户误操作（如误删除账本、错误的全量下载覆盖）或云端数据损坏后，无法回滚到之前任意一天的数据。需要一个独立的云端备份机制，每天留一份可恢复的完整快照。

### 1.2 目标

- **每日一份备份**：每天在云端 `piggycount-bak/` 专属文件夹内留存一份全量备份 ZIP，命名 `PiggyCount-yyyy-MM-dd.zip`
- **当日覆盖**：同一天内多次备份（定时 + 手动）只保留最后一次，每日只留一份
- **完全自包含**：备份 ZIP 包含全部账本数据 + 全部被引用的附件二进制，可脱离现有同步数据独立恢复
- **两种触发模式**：每日固定时间自动触发（App 运行期间）+ 手动随时触发
- **与现有同步机制完全兼容**：数据组织结构（每账本 JSON + 内容寻址附件）、加密方式（E2EE 装饰器透明加密）与现有同步文件字节级同口径
- **高危操作强确认**：全量覆盖（恢复）前连续两次 5 秒倒计时确认，明确告知将覆盖本地数据

### 1.3 非目标

- **不支持 PiggyCount Cloud（路径 B）**：其 REST API 无目录/文件语义，备份卡片对其隐藏（与现有全量同步卡片口径一致）
- **不做自动清理/保留策略**：每日备份长期保留，不自动删除历史备份（可在后续版本扩展）
- **不做后台常驻定时**：App 无后台常驻能力，定时备份仅在 App 运行期间生效；错过的日期不自动补备
- **不做增量备份**：每次备份都是当日全量快照

## 2. 用户故事

### US-1：手动创建全量备份

**作为**一个配置了路径 A 云同步（S3 / WebDAV / Supabase / iCloud）的用户，
**我希望**在云同步页面随时手动创建一份全量备份，
**以便**在做危险操作前留一份可回滚的快照。

**验收标准**：
- 云同步页面「全量同步」卡片下方新增「云端备份」卡片，含「立即备份」入口
- 备份期间显示阻塞进度弹窗（`showBlockingProgressDialog`，不可关闭），实时显示进度文案
- 备份成功后提示云端路径与文件名；失败按现有口径区分认证错误（提示检查云配置）与网络错误
- 上传后云端 `piggycount-bak/` 内存在 `PiggyCount-当日日期.zip`；同日再次备份直接覆盖该文件

### US-2：每日固定时间自动备份

**作为**希望免手动操作的用户，
**我希望**开启定时备份并设定每日时间（默认 22:00），
**以便**每天自动留一份快照。

**验收标准**：
- 卡片内提供「定时备份」开关与时间选择器；设置持久化（SharedPreferences）
- App 运行期间到达设定时间即触发；当日已备份（无论成败）不再重复触发
- 触发条件同时要求：开关开启、云服务为路径 A 已配置状态
- 定时备份为后台非阻塞执行（遵循 auto 类操作不弹阻塞框的既有约定），结果更新卡片上的「最近备份」状态
- 定时备份失败当日不重试，状态显示失败供用户手动补救

### US-3：从备份列表选择并全量覆盖恢复

**作为**一个本地数据丢失/损坏的用户，
**我希望**从云端备份列表选择某一天的备份恢复，
**以便**把全部账本和附件恢复到那天的状态。

**验收标准**：
- 卡片「从备份恢复」入口 → 列出 `piggycount-bak/` 内全部 `PiggyCount-yyyy-MM-dd.zip`（按日期倒序，显示日期与大小）
- 选中后连续两次 `showDangerConfirmDialog`（各 5 秒倒计时），文案明确「将用备份覆盖本地全部账本数据」
- 恢复期间显示阻塞进度弹窗，实时显示逐账本进度
- 恢复语义与现有全量恢复一致：备份中存在、本地也存在的账本 → 整体覆盖；备份独有 → 新建导入；本地独有 → 保留不动
- 附件从 ZIP 内 `attachments/<sha256>.bin` 经 sha256 校验后写入本地缺失文件
- 单账本失败计数不中断，完成后显示成功/失败统计并刷新账本列表、同步状态、统计

## 3. 功能需求汇总

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1 | 备份卡片位于全量同步卡片下方，仅路径 A 云服务显示 | P0 |
| FR-2 | 备份产物为 `piggycount-bak/PiggyCount-yyyy-MM-dd.zip`（本地时区日期） | P0 |
| FR-3 | ZIP 内部结构：`ledger_<id>.json` + `attachments/<sha256>.bin`，与云端同步目录同构 | P0 |
| FR-4 | 加密与传输路径与现有附件上传一致（base64 String 经 E2EE 装饰器透明加密） | P0 |
| FR-5 | 手动备份：无需危险确认直接执行（备份是安全操作），阻塞进度弹窗 | P0 |
| FR-6 | 定时备份：每日固定时间（可配置，默认 22:00），当日一次，非阻塞 | P0 |
| FR-7 | 全量覆盖恢复：备份列表选择 + 双重 5 秒危险确认 + 阻塞进度 | P0 |
| FR-8 | 恢复复用现有导入管线（覆盖/新建/保留语义对齐全量恢复） | P0 |
| FR-9 | l10n 四语言（en / zh / zh_TW / ko）文案完整 | P0 |

## 4. 边界条件与风险

- **大附件量内存峰值**：ZIP 需 base64 后经 String 上传，峰值内存约为 ZIP 体积的 2.2 倍；附件极多的用户存在 OOM 风险（v1 接受，记录于设计文档，后续可改分块上传）
- **加密密码变更**：历史备份密文无法用新密码解密 → 恢复时该账本计入失败并提示，不中断其余账本
- **定时窗口错过**：设定时间早于 App 启动时间 → 当天启动后首次检查立即补触发一次（当日未备份时）；设定时间晚于当天 App 使用时段 → 当天不备份
- **云端 `piggycount-bak/` 内混入其他文件**：列表仅匹配 `PiggyCount-\d{4}-\d{2}-\d{2}\.zip` 命名的文件，其余忽略
- **备份与恢复并发**：卡片各入口互斥（沿用现有 6 个忙碌标志联动模式），防止同时执行
