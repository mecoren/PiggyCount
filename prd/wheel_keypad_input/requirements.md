# 日期/时间选择器数字键盘输入 — 需求文档

> 来源：用户反馈（2026-10-15）「选择日期和时间，在模拟器和投屏的情况下支持数字键盘进行选择」。
>
> 已确认口径（本轮问答）：
> 1. 输入模型 = **定宽数字串**（年 4 位、月/日/时/分/秒各 2 位，敲满自动落到下一段）；
> 2. 覆盖范围 = **仅日期/时间选择器**（不含通用滚轮 `WheelPicker`）；
> 3. 先出本需求文档 + `design.md`，确认后再动代码。

## 一、背景

### 1.1 触屏拖轮在模拟器 / 投屏下的摩擦（本需求的存在理由）

日期与时间全部走 CupertinoPicker 滚轮抽屉（`pick_sheet.dart` 统一外壳）：

| 实现 | 列 | 落点 |
|---|---|---|
| `WheelDatePicker`（`y` / `ym` / `ymd` 三种模式） | 年 / 月 / 日 | `wheel_date_picker.dart:44-237` |
| `_DateStepPicker`（两步流的日期步，ymd 一致） | 年 / 月 / 日 | `wheel_date_picker.dart:282-467` |
| `_TimeStepPicker`（两步流的时间步） | 时 / 分 / 秒 | `wheel_date_picker.dart:470-573` |
| `WheelTimePicker` | 时 / 分 | `wheel_time_picker.dart:35-129` |

滚轮的操作动线是**触碰 + 竖直拖拽**。在 MuMu 模拟器里拖拽要靠鼠标长拖，一格一格对位极难（`itemExtent` 52、可见 3 项）；投屏（scrcpy 等）下注入鼠标的轨迹抖动会被 `CupertinoPicker` 当作抛掷（fling），经常过冲好几格。用户在**有数字键盘在手边**的场景下，最自然的诉求是「直接把数字敲进去」。

### 1.2 同一诉求在金额位已经跑通，地基可直接复用

金额位（纯展示、无输入连接）已经实现了「模拟器硬件键盘 / 投屏注入 / 蓝牙键盘 → 屏幕小键盘既有逻辑」的通路，分两条来源：

| 通路 | 触发者 | 覆盖场景 | 落点 |
|---|---|---|---|
| 框架层 | `HardwareKeyboard.instance.addHandler` | 真机蓝牙键盘 / 桌面端 / widget 测试 | `amount_editor_sheet.dart:1330-1334` |
| 原生 Activity 层 | `MainActivity.dispatchKeyEvent` → `HardwareKeyBridge` | **MuMu 模拟器 / 投屏注入**（这类按键进不了框架层） | `MainActivity.kt:286-308`、`hardware_key_bridge.dart:22-71` |

关键前提（本需求不需要新造通道，只需复用）：

- `HardwareKeyBridge` 的键事件是**广播给所有监听者**的（`hardware_key_bridge.dart:67-69`），抽屉与金额位可各自订阅、各按自身闸门判定；
- 原生捕获是**引用计数**开关：任一 owner 想要即开启（`hardware_key_bridge.dart:47-52`），抽屉关闭必须撤销自己的 owner，否则会留下「无主捕获」（会吞掉数字键、框架层收不到）；
- 记账弹层与日期抽屉**会同时存在**（截图所示动线），但记账弹层的闸门含 `route.isCurrent`（`amount_editor_sheet.dart:1343-1348`），抽屉盖上来后金额位自动让键 —— 冲突已被既有设计消解，只需补测试锁住。

### 1.3 「不弹输入法」是硬约束

金额位那条通路的核心设计是「金额位不可聚焦、不弹 IME」（`amount_editor_sheet.dart:1316-1324` 注释）。本需求同样：**滚轮抽屉不引入任何 `TextField`、不弹输入法**，物理按键只路由到滚轮的既有选值逻辑。否则在模拟器里会多出一个软键盘遮挡卡片。

## 二、需求范围

### R1 日期选择器：定宽数字串直选

- `WheelDatePicker`（`ymd` / `ym` / `y` 三种模式）与 `_DateStepPicker` 支持直接敲数字选日期。
- 定宽：**年 4 位、月 2 位、日 2 位**；敲满一段**自动落到下一段**，无需任何切列按键。
- 值**即时生效**：每敲一位，滚轮立刻跳到对应值（`jumpToItem`），不是敲完才生效。
- 越界裁剪沿用既有语义（`minDate` / `maxDate` 决定的年/月/日可选范围，`wheel_date_picker.dart:82-94`）：日期列的可用上限是**动态的**（随年月变化的实际天数），键入时的越界判定必须读当前动态上限，不能写死 31。

### R2 时间选择器：定宽数字串直选

- `WheelTimePicker`（时/分）与 `_TimeStepPicker`（时/分/秒）支持直接敲数字选时间。
- 定宽：**时 2 位、分 2 位、秒 2 位**，敲满自动落到下一段。
- 范围：时 00-23、分/秒 00-59。

### R3 小键盘可用性：不依赖方向键

数字小键盘上只有 `0-9 . + - * / Enter`，没有方向键。因此：

- **`."/`","`"/"` 作为「分段」键**：定案当前段并前进到下一段。这补上了「只想改某一列」的能力（敲 `.` `.` `15` = 不动年月、只把日改成 15），且完全只用小键盘完成。
- **`+` / `-` 作为当前段 ±1 微调**；有方向键时 `↑` / `↓` 等价。
- **`←` / `→`（含 `Tab` / `Shift+Tab`）切换当前段**：有方向键的键盘（真机蓝牙 / 桌面）才用得上，小键盘用户不依赖它。

### R4 编辑类按键

- `退格`（`Backspace` / `Delete`）：撤销最近一位键入，跨段可用（当前段删空后继续回退上一段）。
- `回车`（`Enter` / `小键盘 Enter`）：等价于顶栏钩子（`√`），定案并返回结果。
- `Esc`：等价于顶栏 X，关闭抽屉并返回 `null`。
- 未被上述规则消费的键一律**不消费**（如 `*`），保持原有放行行为。

### R5 当前段视觉指示（零按键零影响）

- 抽屉打开后**未发生任何键盘键入时，视觉与触摸路径逐像素不变**（不新增文字、不改变高度）——这是硬约束，防止为了键盘通路打扰触屏用户（用户偏好见 `user_profile.md`：固定尺寸/一致栅格）。
- 一旦发生键盘键入，**当前段加一个「输入焦点」描边**，用户据此知道数字落在哪一段。

### R6 覆盖落点

- `WheelDatePicker`、`_DateStepPicker`、`_TimeStepPicker`、`WheelTimePicker` **四处**，共用**一套**键盘驱动，不写四份。
- 主键盘数字（`digit0-9`）与小键盘数字（`numpad0-9`）等价。

### R7 段选择跟随用户（2026-10-15 用户修正）

- 键盘输入的**目标段 = 用户最近点按 / 滚动的那一列**，而不是永远从年段起算。
  - 抽屉刚打开、用户尚未触碰任何列时，仍默认落在**年段**（保持原口径）。
  - 用户点按或滚动某列后，后续数字键一律落进**该列**（含 `-` / `+` 微调、退格的作用段）。
- 理由：用户反馈「应该是选中哪个选项，哪个选项才可以键盘键入，而不是只能从年份开始」—— 实际动线是「先滚到想改的那一列，再敲数字」，强制从年起算会强迫用户多敲两位。
- 与 R3 的关系：R3 的 `.` / `←` / `→` 仍是**不依赖指针**的切段手段，二者叠加（触摸选段 + 键盘切段都生效），不是替代。

### R8 切列不得改写任何列的值（2026-10-15 用户报障修正）

- 切换键盘输入目标列（点按 / 滚动别的列，或键盘的自动前进 / 切段）时，**任何一列的取值与滚轮位置都不得改变**，尤其不得退回「抽屉打开那一刻的初值」。
- 报障现象：月列敲 `2`（月 = 2）→ 点按日列 → 月就变成 `10`（= 打开时初值，2026-10-15 的 10 月）。
- 根因与修法见 `design.md` 决策 11：描边包裹层结构必须恒定，否则该列滚轮元素被重建，`FixedExtentScrollController` 重新 attach 时回到 `initialItem`。

## 三、验收标准

### AC-R1 日期

| # | 场景 | 预期 |
|---|------|------|
| 1 | `ymd` 抽屉打开，键入 `20261015` | 三列滚轮实时跳到 2026 / 10 / 15；回车 → 返回 `DateTime(2026,10,15)` |
| 2 | 只键入 `2026` 后回车 | 年 = 2026，月/日保持打开时的原值（各段未定案缓冲按当前生效值定案） |
| 3 | 键入 `.` `.` `15` 后回车 | 年、月保持原值，日 = 15 |
| 4 | `minDate = 2026-10-01`、初始值 2026-10-15，键入 `05`（月段可选范围 10..12） | 月 clamp 到 10；再键入 `05` → 日 = 5 |
| 5 | 年段键入 `3`（即 3000，超 `maxDate`） | clamp 到年份范围上限（2100），不崩溃、不越界跳转 |
| 6 | `ym` / `y` 模式 | 分别只接受 6 位 / 4 位；回车返回对应模式口径的日期（月、日按 `1` 补齐，与既有 `onConfirm` 一致） |

### AC-R2 时间

| # | 场景 | 预期 |
|---|------|------|
| 1 | `WheelTimePicker` 键入 `7` `0` `5` 后回车 | 07:05（`7` 落在时段的 1 位缓冲，`0` 越界（70 > 23）前推至分段成 `05`） |
| 2 | 键入 `1` `3` `4` `5` 后回车 | 13:45 |
| 3 | `_TimeStepPicker` 键入 `071530` 后回车 | 07:15:30 |
| 4 | 分钟段键入 `9` | 09（1 位缓冲） |
| 5 | 秒段已有缓冲 `9` 时再键入 `9`（99 > 59，且已是末段） | 末段重开语义：秒 = 09（清空缓冲、以新数字重开一位），不崩溃 |

### AC-R3 编辑类按键

| # | 场景 | 预期 |
|---|------|------|
| 1 | 键入 `2026101` 后退格 | 日段缓冲回 `1` → 日 = 1 |
| 2 | 在上一条基础上再退格 | 日段缓冲删空（日值保持 1），再退格回退到月段并删其一位（月 = 1），当前段指示回到月段 |
| 3 | 时段时间段按 `+` / `↑` | 当前段 +1；`0` 时按 `-` / `↓` 停在 `0`，不越界 |
| 4 | `←` / `→` / `Tab` | 切换当前段（定案当前段缓冲、目标段缓冲重置） |
| 5 | `Esc` | 抽屉关闭，返回 `null`（与顶栏 X 同语义） |
| 6 | `*`（小键盘乘号） | 不被消费，不影响任何段的值 |

### AC-R4 通路与闸门

| # | 场景 | 预期 |
|---|------|------|
| 1 | 原生通道回传 Android keyCode（7..16 / 144..153 / 67 / 66 / 160 / 111） | 与框架层逻辑键**完全等价**地走同一处理 |
| 2 | 记账弹层打开、日期抽屉盖在其上，键入 `20261015` | 抽屉正常选值；**记账金额位不变**（`route.isCurrent` 闸门生效） |
| 3 | 日期抽屉关闭后，其后无其它 owner | 原生捕获撤销（`setCaptureOwner(this,false)`）；金额位可接键时捕获仍在 |
| 4 | 全程只用触摸拖轮 | 行为与改动前逐字一致，且**不出现**「当前段描边」（AC-R5） |
| 5 | 备注框等 `EditableText` 持有焦点时打开抽屉 | 不因本通路吞掉输入（沿用「输入框持有焦点则让键」的既有闸门口径） |

### AC-R5 视觉

| # | 场景 | 预期 |
|---|------|------|
| 1 | 抽屉打开、未键入 | 与改动前逐像素一致（无描边、无提示文字、无高度变化） |
| 2 | 首次键入后 | 当前段出现描边，且随切段/自动前进实时移动 |

### AC-R7 段选择跟随用户

| # | 场景 | 预期 |
|---|------|------|
| 1 | `ymd` 抽屉打开后，先**点按/滚动日列**，再敲 `5` | 只有日 = 5；年、月不变；描边落在**日列** |
| 2 | 先点按月列，再敲 `1` `2` `0` `5` | 月 = 12、日 = 5（`1205` 月满 2 位自动前进到日）；年不变 |
| 3 | 敲年段（如 `2026`）触发月/日列联动 `jumpToItem` | 活动段**不被偷走**（联动跳动不得改变活动段，仍是年段） |
| 4 | 打开后不触碰任何列，直接敲 `20261015` | 与改动前逐字一致（默认自年段起算） |
| 5 | 全程只用触摸拖轮 | 行为与改动前逐字一致，且**不出现**描边（同 AC-R5 #1） |

### AC-R8 切列不得改写列值

| # | 场景 | 预期 |
|---|------|------|
| 1 | 初始 `2026-10-15`，月列敲 `2` → 点按日列 | 月轮仍停在第 2 项（2 月）；回车 → `DateTime(2026,2,15)`（月值也不得被回退改写） |
| 2 | 初始 `09:30`，分列敲 `5` → 点按时列 | 分轮仍停在第 5 项；回车 → `09:05` |
| 3 | 任意状态下 | 列包裹层不改变滚轮尺寸（高度恒 156 = `itemExtent` 52 × 可见 3 项） |

## 四、非目标

- **不做输入法 / 文本框输入**：不引入 `TextField`，不弹软键盘（见 1.3）。
- **不改通用滚轮 `WheelPicker`**（`wheel_picker.dart`）：它是通用 `T` 列表（周期频率、结算日在内），语义是「序号」而非「数值」，套数值键入规则会误导（已确认不在本次范围）。
- **不改造触摸手势**：拖动 / 抛掷物理、`dragToDismiss=false`（滚轮型）口径一律不变。R7 只用**指针级监听**（`onPointerDown` + 鼠标滚轮 `PointerScrollEvent`）记录「用户选了哪一列」，它不参与手势竞技场，不改变任何拖动行为（见 `design.md` 决策 10）。
- **不改抽屉视觉基线**：除「键入后当前段描边」外，不加提示文案、不改 `itemExtent` / 高度 / 字号。
- **不引入定时器**：不做「等待 800ms 自动定案」那类超时语义（不可测、手感不确定），定宽 + 越界前推已能覆盖全部歧义。
- 不改日期时间的返回类型与 `onConfirm` 口径（`DateTime` / `TimeOfDay` / `({int hour, int minute, int second})`）。

## 五、边界条件与潜在风险（实现前预判）

| # | 边界 / 风险 | 说明与预案 |
|---|---|---|
| 1 | **原生活塞捕获**（最高危） | 抽屉若只 `addListener` 不 `setCaptureOwner`，MuMu/投屏下完全无效；若只 `setCaptureOwner` 不撤销，抽屉关闭后会持续吞数字键。必须成对，且有测试锁住 |
| 2 | 与金额位抢键 | 依赖既有 `route.isCurrent` 闸门 + owner 引用计数；需新增 AC-R4 #2 用例，避免回归 |
| 3 | 段的动态上限 | 日段上限随年月变化（`wheel_date_picker.dart:91-93`）；键入时的越界判定必须读当前动态上限，不能写死 31 |
| 4 | `minDate` 裁剪后的段起点非 1 | 例如 `minDate=2026-10-01` 时 2026 年的月段范围是 10..12，键入 `1` 会 clamp 成 10。属既定裁剪语义（与触摸拖动一致），但需在测试里显式确认，避免被当成 bug |
| 5 | 年段中间态 | 年段 4 位定宽，键入 `202` 时中间态与「前缀补零」口径相关（见 `design.md` 决策 3），中间态显示值可能不等于用户心里想的前缀 —— **最终值必须正确**，中间态只要不崩溃、单调即可 |
| 6 | 滚轮视觉跟随 | 键盘改了值却不同步 `FixedExtentScrollController`（`jumpToItem`）会造成「值变了但滚轮没动」；且 `jumpToItem` 会触发 `onSelectedItemChanged` 回调，必须与触摸路径共用同一 apply 方法，靠幂等收敛（`design.md` 决策 6） |
| 7 | 无障碍 / 系统键 | 原生捕获集合若把 `TAB` 也吞掉，会影响系统键盘导航与无障碍；故 `TAB` 只走框架层通路，**不进原生捕获集合**（`design.md` 决策 5） |
| 8 | 两步流的中间态 | `showWheelDateTimePicker` 第一步只返回日期、第二步只返回时间（`wheel_date_picker.dart:241-279`），两处独立注册捕获，必须各自撤销（不能只靠外层） |
| 9 | 高亮描边侵入视觉 | 只在「发生过键入」后绘制（AC-R5 #1），触摸用户路径上完全不绘制 |
