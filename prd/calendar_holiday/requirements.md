# 日历节假日与月历样式（calendar_holiday）

> 参考实现：`C:\Develop\project\00_AI\orbit`（桌面 + 移动端同源）
> - 月历样式：`apps/mobile/lib/shared/widgets/shadcn/orbit_month_calendar.dart`
> - 历法副标签：`apps/mobile/lib/core/lunar/{lunar_calendar,chinese_almanac}.dart`
> - 节假日数据层：`crates/orbit-core/src/api/holiday_api.rs`（数据源 timor.tech）
> - 缓存查看页：`apps/mobile/lib/modules/settings/holiday_cache_page.dart`

## 1. 需求理解

把 PiggyCount 现有日历页（[calendar_page.dart](../../lib/pages/calendar/calendar_page.dart)）在**保留收支金额展示**的前提下，升级为 orbit 风格的月历：日期格增加「农历 / 节气 / 节日」副标签与「休 / 班」圆徽标、周末识别色、休息日浅底与调休压暗底，今天改为实心主色块、选中改为主色描边。配套新增可联网更新的**中国法定节假日数据层**：本地缓存 + 冷启动预置兜底 + 每日定时自动更新 + 手动立即更新，并提供独立设置页查看缓存与调整更新时刻。

**第二轮范围扩展**：缓存不再局限于「今年」——支持**按任意年份（2013 ~ 明年，数据源实测下界）联网补写历史节假日**、在设置页**查看过去年份的数据**，并**针对单个年份更新**（设置页「按年份获取」入口 + 年份分组标题上的「更新该年」按钮）。

## 2. 验收标准（AC）

### A. 月历样式（对齐 orbit，保留金额）

- **AC-A1** 每个日期格在数字下方展示副标签，优先级为：公历节日 > 农历节日 > 24 节气 > 农历日（初一显示农历月名，如「八月」）；无副标签时该行不占位（不出现空白行）。
- **AC-A2** 周末（周六 / 周日）数字使用「周末识别色」（区别于普通日文字色），与「休」徽标同源。
- **AC-A3** 放假日（法定节假日 / 调休假）日期格显示浅色识别底；调休补班日（周末要上班）显示压暗底。
- **AC-A4** 有节假日数据的日期格右上角显示 14px 圆徽标：放假为「休」（周末识别色底）、补班为「班」（橙警示色底），白色 9px 文字。
- **AC-A5** 「今天」= 实心主色块 + 白字（今天同时被选中时仍为实心块，不叠加描边）；「选中（非今天）」= 1.5px 主色描边 + 主色数字。两者可同时出现（今天实心 + 另一天描边）。
- **AC-A6** **保留**原收支金额展示（支出 / 收入，超过千 / 万仍按 `-1.2k` / `-1.2w` 缩写）；今天实心块内的金额文字转为白色（对比度不足时不得用彩色），非今天格内金额仍用项目收支语义色。
- **AC-A7** 翻月（横滑 / 标题年月选择器 / 上/下月）后，副标签、徽标、周末色、底色与新月份严格一致；前后月补位日期弱显示且**不**渲染副标签与徽标。
- **AC-A8** 系统大字号 / 应用显示缩放下，日期格不出现 RenderFlex 溢出（文字 `maxLines: 1` + `ellipsis`，日历骨架高度与实际高度一致）。
- **AC-A9** 亮 / 暗黑两套主题下颜色均取 Design Token，无裸色值（`Colors.white/black/grey` 仅允许用于实心块上的白字）。

> **2026-09-29 样式修订（对齐小米日历）**：AC-A5 更新为「选中（含今天被选中）= 实心主色圆角块 + 白字；今天未选中 = 浅主色底 + 主色加粗数字」；AC-A7 放宽为「补位日期弱显数字与农历副标签，徽标与金额仍不渲染」；数字放大加粗（18 / w600）。其余口径不变（AC-A4 14px 徽标、整格底色块、AC-A6 金额保留、AC-A8 大字号不溢出）。

> **2026-09-29 行为修订（按用户需求）**：
> 1. **AC-B8 更新**：自动更新由「每日固定时刻」改为「**每月一次**」——判定口径：从未成功 → 更新；上次成功的日历月 ≠ 当前日历月 → 更新；本月已成功 → 不更新。`holiday_update_meta.fixedHour` 列与设置页「每日更新时刻」项随之下线（v49 未发布，直接改表定义）。
> 2. **AC-C4 更新**：设置页仅保留「每月自动更新」开关，无时刻选择。
> 3. **AC-E2 更新**：「按年份获取」升级为「**按年份范围获取**」——双年滚轮选起止年份（2013 ~ 明年），`fetchYearRange` 补写；单年失败**跳过不中止**，继续拉后续年份，toast 汇总「成功 N + 失败 M」；空响应年份计入「无数据」。**2026-09-30 修订**：分片并发 + 连续失败熔断 + 进度弹窗可取消 + 整次记账一次 + 全失败报原因。
> 其余口径（AC-B7 12 月跨年拉明年、AC-B9 调度范式、AC-E3/E6 记账差异）不变。

### B. 节假日数据层

- **AC-B1** 新增本地 Drift 表缓存节假日行（`date` 主键 + `year` + `isHoliday` + `name` + `fetchedAt`）与单行更新记账表（`lastUpdateMs` / `lastAttemptMs` / `failureCount` / `autoEnabled` / `fixedHour` / `updatedAt`）；`schemaVersion` 48 → **49**，迁移块幂等可重入。
- **AC-B2** 两张表**不进**云同步白名单、**不进**全量备份、**不挂** `updated_at` 触碰触发器（各端自行拉取即可收敛，与 orbit `cfg_holidays` 同口径；参照 `ExchangeRates` 的本地缓存定位）。
- **AC-B3** 全部写操作经 Repository（`HolidayRepository` 抽象 + `LocalHolidayRepository` 实现），**不**经 `ChangeTracker` 记 `local_changes`（非同步实体）。
- **AC-B4** 冷启动 / 无网络 / 首装未拉取时，日历仍能正确显示 2026 年预置节假日（内置兜底表，口径与国务院办公厅 2025 年 10 号文一致）。
- **AC-B5** 联网更新走 `https://timor.tech/api/holiday/year/{year}`，请求带浏览器 UA（服务端 Cloudflare 拦无 UA 客户端），20s 超时；`code != 0` 视为失败。
- **AC-B6** 拉取按「整年替换」语义：事务内先删该年旧行再插入新行；单年失败即整体中止（不留半截数据），失败保留旧缓存并记账 `lastAttemptMs` / `failureCount`，**不**影响日历可用性。
- **AC-B7** 更新年份 = 今年；本地 12 月时额外拉明年（跨年即有数据）。**该口径仅约束自动更新与「立即更新」**；历史年份靠按年获取补写（见 E 组）。
- **AC-B8** 每日自动更新判定（纯函数，可单测）：从未成功 → 应更新；上次成功在今日零点之前且当前已过当日固定时刻 → 应更新（错过则下次启动 / 下轮 tick 补更）；今天已成功 → 不更新。
- **AC-B9** App 启动时触发一次自动更新判定，并挂载分钟级 `HolidayScheduler` 周期检查（对齐 `BackupScheduler` 的 1 分钟 tick + 互斥 + 纯函数判定口径）。
- **AC-B10** 手动「立即更新」无视每日记账强制拉取；成功后 `holidayList` / `holidayMeta` 双失效刷新，日历与设置页同步更新。

### C. 设置页

- **AC-C1** 「我的」页「功能管理」分组新增入口「日历与节假日」，进入独立设置页。
- **AC-C2** 设置页展示缓存概览：总条数（放假 / 补班拆分）、覆盖年份、上次成功更新时间（从未成功显示「从未成功」）、连续失败次数（>0 才显示）。
- **AC-C3** 设置页提供「立即更新」按钮（进行中显示 loading 且禁用），成功 / 失败给出提示。
- **AC-C4** 设置页提供「每日自动更新」开关与「每日更新时刻」选择（底部抽屉单选，选中即应用，与项目抽屉口径一致）。
- **AC-C5** 设置页按年份倒序分组列出节假日行：`M月D日` + 休/班徽标 + 名称，徽标配色与日历页同源。

### E. 历史年份补写与按年更新（第二轮扩展）

- **AC-E1** 支持**按任意年份联网补写**节假日缓存：服务层暴露 `fetchYear(int year)`，走与自动更新同源的接口与整年替换语义（事务内先删该年再插，失败整体回滚、保留旧缓存）。
- **AC-E2** 设置页提供「按年份获取」入口：点击打开**年滚轮**（复用项目既有 `WheelDatePicker` 的 `WheelDatePickerMode.y`），选中年份后联网拉取该年并补写缓存。
- **AC-E3** 设置页每个**年份分组标题右侧**提供「更新该年」按钮，可对列表中已存在的年份就地重新拉取；与「按年份获取」共用同一 `fetchYear` 逻辑。
- **AC-E4** 设置页能**查看过去年份的数据**：缓存条目按年份倒序分组展示（`AC-C5` 的展示口径适用于所有年份，不限于今年）。
- **AC-E5** 补写历史年份**不得**让 2026 预置兜底失效：`loadAll()` 按「年份」粒度合并——DB 已缓存年份以 DB 为准，预置表里未被 DB 覆盖的年份继续兜底；二者不得重复渲染同一日期。
- **AC-E6** 手动补写**历史年份**只记 `lastAttemptMs`（并清零 `failureCount`），**不**写 `lastUpdateMs`；仅当所补年份属于 `yearsToFetch(now)`（今年，或 12 月的明年）时才写 `lastUpdateMs`。目的是**不抑制当天本该发生的自动更新**。
- **AC-E7** 年份可选 / 可写下界为 **2013**（timor.tech 实测有数据的最早年份）、上界为**明年**（`now.year + 1`）；越界不可选。该年线上无数据（空响应）按**成功**处理并提示「该年无数据」，不记为失败。

## 3. 明确不做（本轮范围外）

- **不做** orbit 的「月 ⇄ 周」收展档位（纵向滑动收起月历）。
- **不做** orbit 的年视图 / 议程档 / 事件圆点（PiggyCount 日历定位是「按日看账」，非任务清单）。
- **不做**农历宜忌、生肖年视图标题等 Almanac 扩展（仅移植日用得到的副标签 + 干支，干支留给未来年视图）。
- **不做**节假日数据参与云同步 / 备份（各端自行拉取）。
- **不做**节假日对报表 / 统计 / 账单筛选的联动。
- **不做**港澳台 / 海外节假日源（仅中国法定节假日）。
