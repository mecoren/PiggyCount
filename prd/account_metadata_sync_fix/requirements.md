# 账户元数据同步修复需求（account_metadata_sync_fix）

## 需求理解

用户反馈资产管理（账户）在云同步下载后仍然不同步。排查确认：下载链路中账户导入只在「交易 diff 非空且用户确认应用」时才执行，当云端仅有账户变更（新增/修改账户）而交易无变化时，账户永远无法落到本地；同时同步指纹只覆盖交易，纯账户变更不会让状态变为「云端有更新」，用户甚至收不到下载提示。本次需求让账户像交易一样参与增量同步检测与合并，不引入会覆盖本地数据的全量恢复。

## 背景：根因定位

| # | 缺口 | 位置 | 影响 |
|---|------|------|------|
| G1 | `preview.isEmpty` 直接 `continue`，账户导入无调用时机 | `lib/pages/cloud/cloud_sync_page.dart:881-883` | 云端仅账户变更时下载无效 |
| G2 | `applySyncChanges` 对空变更列表早退，进不到 `importAccounts` | `lib/cloud/sync_diff_service.dart:322-324` | 即使 UI 调用也会被拦截 |
| G3 | `computeDiff` 只比对交易，不比对账户 | `lib/cloud/sync_diff_service.dart:81-200` | 纯账户变更产生空 diff（本次不改 computeDiff，通过元数据无条件合并绕过） |
| G4 | 内容指纹只算 `items`，顶层 `accounts` 不参与 | `lib/cloud/sync_fingerprint.dart:25-94` | 纯账户变更时 `getStatus` 判定 inSync，无「云端有更新」提示，自动提示链路失效 |

## 用户故事

- 作为用户，我在设备 A 新增/修改了账户并上传后，在设备 B 点击「下载」，即使期间没有任何交易变化，账户也应完整出现在设备 B 的资产管理中。
- 作为用户，当云端仅有账户变更时，同步状态应能感知差异（不再误显示「已同步」），启动检查可按既有规则提示。

## 验收标准

1. **AC1（核心）**：dev2 新建账户（不绑定任何交易）→ 全部上传 → dev1 点击下载 → 该账户出现在 dev1 资产管理，且不产生重复账户（syncId/name 去重生效）。
2. **AC2**：云端仅账户字段变更（如余额、备注）时，dev1 下载后本地账户非空字段按云端更新（`importAccounts` 既有 upsert 语义）。
3. **AC3**：账户纳入指纹后，仅账户集合/字段变化 → 本地与云端指纹不同；交易与账户均一致 → 指纹一致。本地与云端指纹均由同一函数在运行时从 JSON 内容计算，无存量指纹迁移问题。
4. **AC4**：交易 diff 非空时的既有预览合并流程行为不变（弹预览框 → 用户选择 → 应用）。
5. **AC5**：用户在预览框取消时行为不变（不应用交易变更；元数据是否合并跟随本次实现策略，见设计文档决策 2）。

## 范围内

- cloud_sync_page 下载按钮的逐账本合并循环（v6+ diff 路径）
- `applySyncChanges` 的元数据导入时序
- `contentFingerprintFromMap` 纳入账户
- 配套单元测试（指纹 + 元数据合并）

## 范围外

- 批量恢复（`restoreAllRemoteLedgers`）跳过本地已有账本的行为（用户已选「增量修复」，全量覆盖类能力不做）
- PiggyCount Cloud SyncEngine 快照导出按 ledgerId 过滤账户的潜伏 Bug（另立需求）
- 分类/标签纳入指纹
- computeDiff 增加账户 diff 条目（预览框展示账户变更明细）
