### 关键流程决策
1. **云配置保护**：清库只删 `app_flutter/piggycount.sqlite*` 与 `attachments/`，绝不碰 `shared_prefs/`。
   云配置 = `FlutterSharedPreferences.xml` 的 `cloud_active_type` + `FlutterSecureStorage.xml`
   的 `cloud_s3_cfg`/`cloud_webdav_cfg`（加密）。清理前后逐字节备份到 `pretest_backup/`。
2. **S3 云端残留槽位治理**：清理前 S3 桶有上一轮 5 个同名槽位；因「全量上传」不清理云端独有账本
   （`slotKey = 账本 syncId`，`pathForLedger` 见 `transactions_sync_manager.dart:703-718`），
   把本轮 5 个账本 `sync_id`（含 `local_changes.entity_sync_id`、`ledger_members.ledger_sync_id`）
   对齐到旧槽位 syncId，实现**就地覆盖**。验证：B 端云端发现恰好 6 个。
3. **后端切换**走应用自身 UI（我的 → 云服务 → 卡片 → 确定），不做 prefs 手工改写；
   测试后**恢复为 s3**，并把两端本地库还原为 S3 轮快照，使两端 `SyncDiff.inSync`、0 次上传
   （避免 WebDAV 轮的新 syncId 在 S3 桶产生 5 个新增槽位污染）。

### 工具链经验（重要，已同步至 MEMORY.md）
- `adb exec-out` 取代 `adb shell cat`（后者做 `\n→\r\n` 转换，拉 sqlite 必损坏）
- `adb push` 必须用 Windows 原生路径（`D:/...`）；MSYS 的 `/d/...` 会被 adb 判为不存在，
  这正是历史报告里"大文件静默失败"的真实根因
- `adb shell` 输出行尾 `\r`：循环拼路径前必须 `tr -d '\r'`
- `run-as PKG sh -c "rm -rf path/*"` glob 不展开 → 直接对目录 `rm -rf`
- 设备端 `/system/bin/sqlite3` 可用：`force-stop` → `VACUUM INTO` → `exec-out` 拉取
- `inject_16384_sync_test.py` 的附件段依赖 Pillow，隔离 venv 安装（`envs/default`）
- 新增 `scripts/live_db/run_20260913/start_webdav_local.py`：在内存中把
  `webdav_server.py` 的绑定从 `0.0.0.0` 改为 `127.0.0.1`（该 fixture 不强制鉴权，
  不宜暴露到局域网；模拟器 `10.0.2.2` 本就映射宿主 loopback），不动仓库 fixture。
