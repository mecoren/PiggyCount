### 工具链经验（重要，已同步至 MEMORY.md）
- `adb exec-out` 取代 `adb shell cat`（后者做 `\n→\r\n` 转换，拉 sqlite 必损坏）
- `adb push` 必须用 Windows 原生路径（`D:/...`）；MSYS 的 `/d/...` 会被 adb 判为不存在，
  这正是历史报告里"大文件静默失败"的真实根因
- `adb shell` 输出行尾 `\r`：循环拼路径前必须 `tr -d '\r'`
- `run-as PKG sh -c "rm -rf path/*"` glob 不展开 → 直接对目录 `rm -rf`
- 设备端 `/system/bin/sqlite3` 可用：`force-stop` → `VACUUM INTO` → `exec-out` 拉取
- `inject_16384_sync_test.py` 的附件段依赖 Pillow，隔离 venv 安装（`envs/default`）
- 新增 `scripts/live_db/run_20260913/start_webdav_local.py`：在内存中把
  `webdav_server.py` 的绑定从 `0.0.0.0` 改为 `127.0.0.1`（该 fixture 不强制鉴权，
  不宜暴露到局域网；模拟器 `10.0.2.2` 本就映射宿主 loopback），不动仓库 fixture。

### 关键新发现
1. **WebDAV 测试服务器必须用常驻后台任务启动**（首次 `nohup ... &` 随 shell 调用返回被回收，
   表现为 A 端 `Connection refused` + UI 弹「6 个账本同步状态检查失败（网络或超时）」）。
   启动后必须 `netstat` 确认 LISTENING 再跑 UI。
2. **S3 桶在开测时可能是空的**：A 端启动日志 `云端指纹: 无` → 无残留槽位，
   syncId 对齐仅为预防性动作（B 端发现数 = 6 证明桶内恰好 6 槽位）。
3. **更正历史结论**：附件二进制**确实随导入恢复到 B 端**——WebDAV 服务端可观测到 B 端
   `GET attachments/*.bin`，且 B 端 `app_flutter/attachments/` 实测落盘 6 个文件，
   文件名 == 内容 sha256（6/6），与服务端对象逐字节相同。
4. **附件计数口径**：7 行挂载 → 6 个内容唯一文件（跨账本同内容去重）；
   本地库 `cloud_sha256` 为 NULL，比对靠 `file_name`/`local_sha256`。
5. **微信/支付宝笔数三种口径**（报告必须声明）：注入脚本自报 1852 / 账户维度全部类型 1923 /
   仅 expense+income 1656。
6. 收尾顺序：**先还原本地库快照、再切回后端**；切回时可能弹「云端有更新」→ 点**「暂不合并」**。
