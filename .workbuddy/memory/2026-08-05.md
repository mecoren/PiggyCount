## 修复 S3 云同步 HTTP 400（ListObjects 失败）
- 背景：S3Provider.initialize() 调用 listObjects 报 `HTTP 400: Your browser sent a request that this server could not understand`（Apache 风格 HTML），请求在 HTTP 层即被拒，未进入签名校验。
- 根因（三类代码缺陷）：① 硬编码 path-style 寻址（`/bucket/...`），OSS/COS/AWS/R2 等托管云要求 virtual-hosted-style；② `useSSL` 默认 true 且未归一化 endpoint 协议前缀；③ ListObjectsV2（`?list-type=2`）在部分兼容网关（如阿里云 OSS S3 兼容层）不被支持。
- 改动：
  - 新增 `packages/flutter_cloud_sync_s3/lib/src/s3_endpoint.dart`：`parseS3Endpoint`（剥离协议前缀/路径、协议推导 useSSL、解析 host 端口）、`isManagedCloudEndpoint`（识别 AWS/OSS/COS/R2/B2/Wasabi/DO/Qiniu 等托管云）。
  - `s3_client.dart`：新增 `forcePathStyle`（默认 true）；`_buildUri` 支持 virtual-hosted（`bucket.endpoint`）与 path-style 双模式；`Host` 头改用 `uri.authority`（非默认端口带端口，签名与 wire 一致）；`listObjects` 在 V2 返回 400/501 时自动回退 ListObjects V1；`_handleError` 对非 XML（HTML）错误体做净化并给出排查提示（endpoint/useSSL/寻址方式/API 版本）。
  - `s3_provider.dart`：使用 `parseS3Endpoint` 归一化；`forcePathStyle` 默认 = `!isManagedCloudEndpoint(host)`（托管云 virtual-hosted，自托管 path-style），可用配置覆盖。
  - `cloud_service_config.dart`：新增 `s3ForcePathStyle` 字段并同步 toJson/fromJson；`provider_factory.dart` 传入 `forcePathStyle`。
- UI 默认值（cloud_service_page.dart）：WebDAV 远程路径未配置时默认 `/PiggyCount`（`/${appName}`）；S3 存储桶未配置时默认 `piggycount`（`appName.toLowerCase()`，S3 桶名要求小写）。仅首次配置生效，已有配置保留原值。
- 测试：新增 `packages/flutter_cloud_sync_s3/test/`（s3_endpoint_test.dart、s3_client_test.dart，共 16 用例，MockClient 验证寻址/Host/签名/回退/净化）。S3 包 16 通过；flutter_cloud_sync 包 59 通过；主应用 test/cloud 125 通过；flutter analyze 无新增告警。

## S3 桶名 hint 与默认值冲突修复
- 问题：S3 桶输入框 hint 文案 `piggycount` 与默认值 `piggycount` 完全相同，用户无法区分"字段已填默认值"与"字段空、仅显示 hint"，导致保存时出现"存储桶名称不能为空"的误判。
- 修复：将 4 个 ARB 中 `cloudS3BucketHint` 改为明确的示例值：`zh/zh_TW: "例如 my-bucket"`、`en: "e.g. my-bucket"`、`ko: "예: my-bucket"`，重新 `flutter gen-l10n`。
- 默认值（`appName.toLowerCase()` = `piggycount`）仍保留，确保首次配置时字段自动填充；仅在用户清空字段时才显示 hint。
