## PiggyCount 同步加密 + UI 全面审查

完成对 PiggyCount 项目的深度审查，覆盖同步功能、同步加密、UI 三层。
报告输出至 `docs/security-and-ui-audit-2026-08-20.md`（约 15.7KB）。

### 关键结论（按风险排序）
- **S1+S2 联动致命链**：增量拉取解密失败被静默丢弃且游标前进（S1，`sync_engine.dart:1271-1284` + `sync_engine_apply.dart:19-23`），叠加改密未重加密 `sync_changes` 增量日志（S2，`encryption_service_impl.dart:362-422`），在"改密后加入新设备"场景可导致真实数据丢失。
- **S3 高危**：PiggyCount Cloud 会话令牌（accessToken/refreshToken）明文写入默认 SharedPreferences（`piggycount_cloud_provider.dart:1757`）。应改用 FlutterSecureStorage。
- **S4 高危**：S3 后端允许明文 HTTP，且 endpoint 带 `http://` 前缀会强制 useSSL=false（`s3_client.dart:574` + `s3_endpoint.dart:36`）。WebDAV 已硬性拒绝非 HTTPS。
- **S5 高**：自建存储（WebDAV/S3/iCloud）整账本快照覆盖模型，离线并发编辑后选边致另一端数据整体丢失。
- **UI**：U1（i18n 漏网硬编码中文）、U4（全局 TextScaler 仅缩放文字不缩放容器致大字体裁切）、U3（触摸热区 <48px）、U2（暗色模式硬编码色多处）。

共记录 S1-S15、U1-U9，含已确认优点与需产品决策取舍（S6/S7 主密码门控与派生密钥落盘）。
