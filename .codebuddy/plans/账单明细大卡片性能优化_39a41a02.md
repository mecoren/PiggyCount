## 产品概述

优化首页"明细"Tab 在导入大量账单（3000笔）后的列表卡顿问题。根因是"整张大卡片"渲染模式（`wrapInOuterCard: true`）把全部交易一次性构建进单个 Column，完全绕过了 FlutterListView 的懒加载机制，导致每次 rebuild 都 O(n) 全量重建所有复杂 Item。

## 核心功能

- 将"整张大卡片"改为"每天一张独立日卡片"，通过 FlutterListView 的 delegate 按 index 懒加载，滚动时仅渲染可视区域
- 保留大卡片模式的视觉风格：日卡片 SectionCard 样式（margin + 圆角 + surface + 阴影/边框）、DaySectionHeader + 当天交易集合、日间细线分隔、日卡片内无日内分割线
- 保持既有功能不变：首页月份跳转（jumpToMonth 依赖 `_dateIndexMap`）、可见性跟踪（onDateVisibilityChanged）、底部悬浮 Tab 栏 bottomSpacer、滑动删除（Dismissible）与标签/附件交互

## 边界说明

- 本次仅聚焦渲染策略本身（方案 A），数据查询层分页、每个 Item 的 provider 订阅重建属于后续可选优化，不在本次范围内

## 技术栈

- Flutter + Riverpod（flutter_riverpod）+ flutter_list_view（第三方懒加载列表）+ Drift（数据库）
- 沿用现有架构与模式，不改动数据层、状态管理、路由

## 实现方案

### 核心策略

在 `transaction_list.dart` 中，不再用 `_buildOuterCard` 一次性构建所有 day，而是让**每个 day 渲染为一张独立的日卡片**，作为 FlutterListView delegate 中按 index 懒加载的一个列表项。这样 3000 条数据下，滚动时 FlutterListView 只构建可视区间的日卡片，其余回收。

### 关键技术决策

1. **改造 `_flatItems` 构建（`_buildFlatItems` L323-339）**：大卡片模式下，为每个 day 的 flat item 携带渲染所需信息（dateKey + 当天交易列表 + 该 day 在卡片序列中的位置标识，用于决定是否画上边框圆角等），替代"首个 day 全量、其余占位"的旧结构。
2. **新增"日卡片"构建方法**：抽取 `_buildOuterCard` 中"单日"的渲染逻辑（DaySectionHeader + 当天交易行集合 + 卡片容器样式）为独立方法，让每个 day flat item 在 delegate 中调用它。day 之间不再用独立 dayDivider item，而由卡片自身 margin/间距体现。
3. **保留 jumpToMonth 与可见性跟踪**：`_dateIndexMap` 仍映射到每个 day item 的 index，month 跳转逻辑不变；DaySectionHeader 继续包 `VisibilityDetector`。
4. **复用 `_buildTransactionRow`**：每张日卡片内的交易行继续复用现有 `_buildTransactionRow`（L500-655），保持滑动删除、标签/附件交互不变。

### 性能预期

- 旧实现：每次 rebuild 构建全部 3000 条交易 Widget，成本 O(n)，且整张大卡片无法滚动回收。
- 新实现：delegate 按 index 构建，单帧仅构建可视区（约一屏 5~10 天、几十条交易），滚动时重用/回收子项；`_buildFlatItems` 的分组排序 O(n log n) 保留（数据量 3000 级别可忽略）。

### 执行注意（防回归）

- **不要改动数据层**：repository 无分页、Drift watch 全量重发、每个 Item 的 provider 订阅，均不在本次范围，避免扩大爆炸半径。
- **保持 `_flatItems` 的 record 结构兼容**：`_buildFlatItems` 与 delegate 需同步修改，避免 type 分支与数据字段不匹配导致类型/空安全错误。
- **样式延续**：日卡片需复用 `PiggyDimens.cardMargin`、`PiggyTokens.surface`、`PiggyTokens.radiusLg`、`PiggyShadows.card`、`PiggyTokens.listDayDivider*`，保证视觉与大卡片一致。
- **月份跳转 key**：`VisibilityDetector` 的 `Key('header-$dateKey')` 与 Dismissible 的 `Key('tx-${id}-$flatIndex')` 需保留，避免 state 复用错乱。

## 架构设计

改动集中在 `transaction_list.dart` 的渲染层，单文件内职责划分：

- `_buildFlatItems()`：调整大卡片模式的 flat item 结构，让每个 day 携带渲染信息
- 新增 `_buildDayCard(context, index, dateKey, list, flatDayIndex)`：渲染单张日卡片
- delegate 中 `type == 'day'` 分支：改为对每个 day 调用 `_buildDayCard`，替代原来"仅首个 day 返回 `_buildOuterCard`、其余占位"的逻辑
- 移除/替换 `_buildOuterCard` 的全量构建（其单日渲染逻辑下沉到 `_buildDayCard`）
